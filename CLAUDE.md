# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

**GAO Remake** — a 2D top-down RPG built in **Godot 4.7** (Mobile renderer, 640x360 viewport drawn at 2× in a 1280x720 window, the world at camera zoom 2 -- 320×180 of it on screen -- nearest-neighbour filtering). The setting draws on *Sword Art Online* lore (a floating-castle world of stacked floors, players trapped in a death-game VRMMO, sword-skill combat). Planned core systems: **inventory**, **turn-based combat**, **quests**, and **dialogue**.

The world is **100 floors** of a stacked castle, each ending in a boss; floor 100 is the final fight. Milestone floors are hand-authored, the rest are procedurally generated — see "The floor system" below.

`plan.md` is the roadmap and the source of truth for what's built. **M0 (foundation), M1 (overworld, movement, interaction, map transitions), M2 (dialogue), M3 (inventory & items), M4 (turn-based combat), M5 (quests) and the 100-floor spine are done.** What's left is M5.5 (exploration feel), M6 (world depth, authored floors) and M7 (save/load, polish, audio). **M5.5 is under way**: the camera is close (320×180 of world on screen), monsters wander, chase and start fights on contact, and every generated floor ends in a labyrinth — several screens of it, dark beyond your line of sight — whose boss door only shows once you walk into its room, with fog of war and a map screen (**M**) to find it by, drawn in ink on parchment. The map passed playtest; the battle screen did not, and was replaced by **fighting on the map itself** (Chrono Trigger-style, plan.md M5.5 §6, done): fights are staged where they happen under slim `BattleHud` plates, the HUD's vitals plate staying up -- monsters at ×2 zoom, and bosses step out of their doors, at ×2 where they fit and ×1 where they don't. There is no battle screen any more. The §4 floor-structure design pass is decided and under way: **every labyrinth has a safe zone** (a campfire room on the way to the door that monsters won't enter, where **E** rests you to full); **gilded chests** (the pack's big red one) always hold gear and are usually trapped -- an alarm or a teleport into the labyrinth; and four **puzzles** are in the field rooms -- a wisp that leads you The core loop is completable end to end: walk, talk, take a job, fight the monsters on the floor, level up, beat the floor boss, climb. No placeholders remain in it.

**Dialogue is custom, not Dialogic** — decided so dialogue stays on the same `Resource`/`.tres` model as items, skills and quests, and conditions can read `GameState` flags directly. See "The dialogue system" below.

## Commands

Godot has no separate build step; the editor imports assets and the engine runs scenes directly. The engine binary lives inside the installed app:

```sh
GODOT="/Applications/Godot.app/Contents/MacOS/Godot"

# Run the game (main scene). It boots to the title screen. `-- --slot=2` skips it and
# continues slot 2 (or starts a new game there if it is empty), `-- --slot=2 --new`
# starts over in it (the first autosave overwrites the old save). A debug
# `-- --floor=N [--level=L]` start is a scratch run and saves nowhere.
"$GODOT" --path .

# Run a specific scene without changing the main scene
"$GODOT" --path . res://path/to/Scene.tscn

# Headless import (regenerate .godot/ import cache, e.g. in CI or after adding assets)
"$GODOT" --headless --path . --import

# Open the editor
"$GODOT" --editor --path .
```

`.godot/` is generated import/cache output and is gitignored — never edit it by hand. If imports look stale, delete `.godot/imported/` and re-run the import command.

### Tools

Run in this order — each step consumes the previous one's output.

```sh
# 1. Placeholder art: one atlas per biome (8 semantic slots + a 47-tile wall
#    blob), plus characters, dialogue
#    portraits, props and enemy battlers (pure-stdlib PNG writer, no Pillow).
#    Item icons are not drawn here any more -- see step 3c.
python3 tools/gen_placeholder_art.py

# 2. Re-import, so step 3 cuts tiles from the atlas step 1 just wrote rather than
#    from the stale one. Load-bearing, not housekeeping.
"$GODOT" --headless --path . --import

# 3. A TileSet + BiomeKit per biome. Safe to re-run; only touches derived resources.
#    Biomes listed in PACK_BIOMES (all ten, now) are cut straight from
#    assets/ninja_adventure/ and embedded, so they don't depend on step 2.
"$GODOT" --headless --path . --script res://tools/build_biomes.gd

# 3b. The UI's font faces (ui/theme/ui_font.tres, ui_font_strong.tres: Exo 2 at two
#     weights) and two themes, ui/theme/gao_theme.tres (menus) and glass_theme.tres
#     (over the map), framed from assets/kenney_fantasy_ui/ in UiPalette's colours.
#     OVERWRITES all four -- edit the tool or the palette, never the .tres. Needs
#     assets/fonts/Exo2-Variable.ttf imported (step 2).
"$GODOT" --headless --path . --script res://tools/build_ui_skin.gd

# 3c. Item icons: one 16x16 PNG per item in assets/icons/items/, cut from the
#     pack's item set and padded onto a tile (or drawn from a table in the tool).
#     ICONS must name every id in ItemLibrary.ITEMS; re-import after.
"$GODOT" --headless --path . --script res://tools/build_item_icons.gd

# 4. The Town of Beginnings, Floor 1's first map.
#    OVERWRITES scenes/world/town.tscn -- stop using it once the town is being
#    painted in the editor.
"$GODOT" --headless --path . --script res://tools/build_placeholder_maps.gd

# 5. The authored floors: Floor 1's West Field (field.tscn), Floor 10 and Floor 25.
#    Same caveat: each OVERWRITES its scene. All extend tools/authored_floor.gd,
#    which refuses to write a floor with anything on it unreachable from the spawn,
#    a labyrinth seed that grows no camp, or a puzzle that doesn't fit where the
#    layout pins it -- so a bad edit to a layout table fails here rather than in the
#    game. Add `-- --preview` to print the layout as text instead of writing it.
"$GODOT" --headless --path . --script res://tools/build_floor_01.gd
"$GODOT" --headless --path . --script res://tools/build_floor_10.gd
"$GODOT" --headless --path . --script res://tools/build_floor_25.gd

# Boot the game, capture frames to user://screenshots, exit (needs a real window).
# `-- --puzzles` / `-- --cracks` / `-- --world` / `-- --bosses` / `-- --phases` / `-- --gates` / `-- --camps` / `-- --villages` / `-- --shapes` / `-- --dungeons` / `-- --modifiers` / `-- --events` / `-- --landmarks` / `-- --rooms` / `-- --shops` / `-- --forge` / `-- --title` / `-- --menu` / `-- --idle` run just those passes.
"$GODOT" --path . res://tools/screenshot.tscn
```

Biome atlases share one **semantic slot layout** in row 0 (`0 floor, 1 floor-alt, 2 path, 3 special, 4 liquid, 5 obstacle, 6 wall, 7 wall-alt`; slots 4–7 collide). The generator paints "wall" without knowing which biome it's in, so a new biome is a palette entry in `gen_placeholder_art.py` plus a row in `build_biomes.gd` — no generator changes.

A **pack biome** keeps the same row-0 slots and adds the rows placeholders lack — grass/dirt and water transitions, 2×2 trees, decor, houses, and for a cliff biome a composed wall blob — laid out by `PACK_BIOMES` in `build_biomes.gd` as sheet-and-cell references into the pack. Its transitions' terrain peering bits are read off the pixels (`_links`), never typed in, for the reason the blob derives its masks from a rule.

Rows 1–6 hold the **47-tile wall blob** for autotiling. Both tools derive the mask list from the same rule (`_blob_masks`) rather than sharing a table, so the art and the terrain peering bits cannot drift into a silent mis-pairing — and the floor test checks every chosen tile against its actual neighbours in case they do.

Maps are engine-generated because `tile_map_data` is a binary blob inside the `.tscn` — it can't be hand-authored as text. Entity scenes (player, NPC, chest, exits) are plain hand-written `.tscn`.

All eight exit non-zero on failure. Eight checks are load-bearing and should not be weakened:

- **The floor test's completability flood fill.** An unreachable boss door is the failure mode procedural generation reliably ships, and playtesting will not find it. It also checks the outer ring is still sealed: autotiling rewrites every wall on the floor, and dropping one instead of replacing it would open the map onto the void — which the flood fill alone would answer by quietly reaching *further*, not by failing. **Authored floors get the same walk**, since hand-building fails at this the same way and with no seed to blame; that walk follows `MapExit`s, because an authored floor may span several maps (Floor 1's door is in the field, not the town). Its flood fill is *bounded* to the walls' used rect — an authored map is allowed holes in its border where an exit sits in them, and an unbounded fill walks out through one and expands forever. Whether a map's ring must be sealed is decided *per map*: an exit to another map excuses holes, an exit back into the same map (Lanternfall's lift) does not. **And a hidden door must be findable**, which no flood fill sees: `_audit_labyrinth` checks the door hides in exactly its boss room, the room has one doorway, the labyrinth is open only at its mouth and walling that up puts the door out of reach, the maze has dead ends, and its safe zone stands on the one way to the door (walling it up cuts the door off) with its fire in it and no monster starting there — plus, across all floors, that the door is not always the farthest point and never under 24 tiles in. **And every puzzle must be solvable** (`_audit_puzzles`): a wisp's path is floor step by step to its shrine, every piece and sealed chest can be walked up to with every piece solid, an ordered rite's order is a permutation its tablet names, a timed one burns at least 1.25x the real walk round it, a statue ring stands round its altar solved facing it and is solvable and at least 4 turns out, the pieces leave the floor's own chests, fire and door approachable, and a vault can't be entered shut, can be open, and every sigil it wants is in exactly one chest reachable without it. A cracked wall's doorway and hollow are rock until broken (so the completability walk skips its chest), and broken the game's way the hollow opens only at its doorway, its chest is reachable, and every wall, forest edge and ground cell round it is dressed right; the formation sweep then runs on the broken floor, so a fight can be staged in the hollow.
- **The floor test's formation sweep.** A fight on the map needs somewhere to stand, and a cell with no formation is a fight with nobody on the map, in one corner of one floor nobody playtests. At every cell a body can walk to from the spawn (standable cells -- a chest-boxed pocket the wall flood reaches is not one), on every generated floor and every authored map with monsters, `GameMap.formation()` must find spots on floor in the same region, the player slid only to a cell walkable inside the slide box (never through a wall), and a clear lane to the enemy. It runs off the map's nodes, not physics (`refresh_solids()`), which is why it works on maps never added to the tree. **Bosses get the same sweep from every cell within two of their door**, on all 100 floors: `GameMap.boss_formation()` must stand every enemy on floor, walk the player back no more than `BOSS_WALK` steps, keep a clear lane, and draw no two fighters over each other — the last being what its body-sized gaps are for.
- **The combat test's balance section.** Its numbers were measured, not chosen. Hisukurifu was measured at 10/16 at the level the check fights him at and 0/8 twelve levels short -- the hardest fight in the game, on purpose. A stat, curve or growth-rate edit that makes floor 50 unwinnable fails here instead of 20 hours into a playthrough. If one moves, decide whether the climb *should* have changed shape before re-baselining it.
- **The inventory test's item-id sweep.** Every id the rest of the game emits — `EnemyType.loot`, `FloorGenerator.CHEST_*`, `FloorPuzzles.SEALED_LOOT`, `FloorEvents`' pay, every authored floor's chests, dialogue's `GIVE_ITEM`, every shop's wares — must name a real `.tres`. A typo is silent everywhere else: the drop simply never arrives.
- **The inventory test's economy check.** On kills alone — `FloorTuning.monster_count(n)` at the pool's average Col, plus the boss — every ware must be affordable once the floor it unlocks on (`Item.shop_floor`) is cleared. Prices are fixed and income linear, so it bites low down, where the prices were set against it. A price or a Col curve edit that fails it is a shelf the player can't buy from.
- **The quest test's objective-target sweep.** The same failure, one layer up: every KILL must name an enemy id, every COLLECT an item id, every TALK a conversation, every REACH a floor in range. A typo makes an objective that can never be completed, and nothing else in the game will say so. It sweeps the shipped quests *and* every job `LocalQuests` and `FloorEvents` can build, on every floor of two saves -- a template is ninety quests' worth of typo.
- **The save test's field sweep.** Every variable of `GameState`, `Inventory` and `QuestLog` must be in that autoload's `SAVED` or `NOT_SAVED` list, and the lists must name nothing that isn't there. A field added later and left out of `to_save()` is progress the player loses on every load, silently, and no other test sees it. Adding state to one of those autoloads: write it in `to_save()`/`from_save()` and list it in `SAVED`, or list it in `NOT_SAVED` and say why. The round trip beside it -- a save of the loaded game must be the save it was loaded from, field for field -- catches a field listed but written wrong.
- **The audio test's id sweep.** Every `Audio.play(&"...")` in any script or scene, every `SkillFx.sound`, a waystone's or lever's `sound` and every track a page asks for must be in `SoundLibrary.SOUNDS` / `MusicLibrary.TRACKS`, and every file there must load. It reads the source, so a new call is covered the moment it is written -- but only in that spelling: a sound id passed through a variable needs its own line in the test. A missing sound is silence, which no one reports.

Run it as a **scene**, not with `--script`: autoloads are registered *after* a script main loop is compiled, so `EventBus`/`GameState`/`SceneRouter` don't resolve there.

For unit tests, prefer [GUT](https://github.com/bitwes/Gut) (not installed yet). Once it's in `addons/gut/`:

```sh
"$GODOT" --headless --path . -s res://addons/gut/gut_cmdln.gd -gdir=res://test -gexit
"$GODOT" --headless --path . -s res://addons/gut/gut_cmdln.gd -gtest=res://test/test_inventory.gd -gexit
```

## Architecture conventions

Godot projects are trees of **scenes** (`.tscn`) composed of **nodes**, with behavior in **GDScript** (`.gd`) attached to nodes. Prefer this Godot-idiomatic structure over a monolithic manager:

- **Autoload singletons** (Project Settings → Autoload) for cross-scene state that must persist: e.g. `GameState`, `Inventory`, `QuestLog`, `PartyManager`. These are the backbone of the four systems — combat, dialogue, and quests all read/write them. Access them by their autoload name from anywhere.
- **Signals over polling.** Systems communicate by emitting signals (e.g. `inventory.item_added`, `combat.turn_ended`, `dialogue.finished`, `quest.objective_completed`). UI subscribes to these rather than the model reaching into the UI. A global event bus autoload is acceptable for decoupled cross-system events.
- **Data as Resources.** Model items, enemies, skills, quests, and dialogue trees as custom `Resource` classes (`extends Resource`, `@export` fields) saved as `.tres` files. This keeps content data-driven and editable in the inspector rather than hard-coded. Combat and inventory operate on these resources, not on ad-hoc dictionaries.
- **Scene boundaries mirror game modes.** The overworld (top-down exploration) and turn-based combat are typically separate scenes; entering combat swaps/overlays the combat scene and returns to the overworld afterward, carrying results through the autoloads.

Top-level layout: `assets/` (`placeholder/` generated art, `ninja_adventure/` the art pack with its LICENSE), `scenes/` (player, world, main), `scripts/` (`autoload/`, `combat/`, `inventory/`, `player/`, `quests/`, `resources/`, `world/`), `resources/` (the `.tres` data: `biomes/`, `dialogue/`, `enemies/`, `floors/`, `items/`, `quests/`, `skills/`, `statuses/`, `tilesets/`), `ui/`, `assets/`, `test/`, `tools/` (generators), `addons/` (plugins like GUT).

### What exists (M0/M1/M2)

- **Autoloads** — `EventBus` (signals only, no logic; signals for all four systems are already declared), `GameState` (stats, level/XP curve, world flags, a *counted* input lock), `Inventory`, `QuestLog`, `SceneRouter`, `DialogueRunner`, `CombatManager`, `SaveGame`, `Settings`, `IdleWatch`, `Audio`.
- **`scenes/main.tscn` is the main scene and never unloads.** Maps are swapped in and out of its `WorldRoot` by `SceneRouter.change_map(path, spawn)` — not via `change_scene_to_file`, so the HUD and fade overlay survive transitions. A map arrives at a *named spawn point*; `GameMap._ready()` resolves the name and places the player.
- **`Interactable`** (`scripts/world/interactable.gd`, physics layer 4) is the base for NPC / chest / map exit / boss gate / monster. The player's `InteractSensor` picks the nearest one it's facing and announces it via `EventBus.interact_target_changed`.
- **Interaction goes deaf for `Player.INTERACT_GRACE` after a box closes.** A conversation ends on the same press that closed it, and a player mashing through text is still pressing **E** a few frames later -- straight back into the NPC they just finished with. The player listens for `EventBus.dialogue_finished`, so chests, signs and system notices are covered by the same rule.
- **Persistence is flags, not node state** — e.g. an opened chest sets `GameState` flag `chest_town_square`, so it stays open across map reloads. Monsters are the deliberate exception: they are `queue_free()`d and come back on the next visit, because a player who has hit a wall needs somewhere to earn levels.
- **The map screen (M) is a hologram**, as SAO draws its own: a dark sheet (`MapPanel`, written in `MapLabel`); walked floor bright, glimpsed floor a shade under and stippled, rock a dark wash with a bright edge, the unexplored extent a deeper dotted wash. Every colour is a `UiPalette.MAP_*`. Symbols are `MapGlyph`s (`ui/map_glyph.gd`) -- pixel tables with a derived ink outline, drawn at one-unit pixels (half a world texel), shared by the view and the legend; the legend is one row and full, so a new symbol costs a word somewhere else. A violet glint marks an unsolved puzzle (the wisp, a rite's tablet, a sealed door, a crack once seen), a blue chest a sealed one. A `!` marks what the *tracked* quest wants on this map (its giver when ready, a TALK target, the door for a REACH of this floor). `GameMap.region` subtitles it and `GameMap.landmarks` (name → rect) labels places once seen -- the generator names the labyrinth, authored floors pass a `LANDMARKS` table to `_name_places()`.
- **`EventBus.input_lock_changed`** fires as the counted lock goes on and comes off; the HUD's prompt steps aside on it, so a screen that holds the lock never has the prompt drawn through it.
- **`ui/hud.gd` is the interact prompt and the player's vitals** -- the game's one vitals plate: in a fight it stays up, grows a poise bar and a status line, and follows the player's `Combatant` until the fight writes back. Conversations live in `ui/dialogue_box.tscn`; a fight's message line and command menu in `ui/battle_hud.tscn`, the fight itself on the map (`ui/battle_stage.gd`); the tracked quest in `ui/quest_tracker.tscn`; the bag, the journal and the map are tabs of `ui/game_menu/` (see "The game menu"). The prompt hides during either.

Physics layers: 1 world, 2 player, 3 enemy, 4 interactable. Input actions: `move_up/down/left/right`, `interact`, `inventory`, `journal`, `map`, `pause` (Esc), `quick_save` (F5), `quick_load` (F9).

### The save

- **Each autoload owns the shape of its own state; `SaveGame` owns everything round it.** `GameState`, `Inventory` and `QuestLog` each have `to_save()` → a JSON-safe `Dictionary` and `from_save(data)`, plus the `SAVED`/`NOT_SAVED` lists the save test sweeps. `SaveGame` (autoload) owns the slots (`user://saves/slot_<n>.json`, 1–3), the file's `version` and `_migrate()`, when to write, and putting the player back. Nothing else reads or writes a save file.
- **What is saved is state, never a map.** Generated floors aren't saved: `GameState.world_seed` is, and every floor grows back from it exactly. Everything that stays done -- chests, puzzles, found doors, broken walls, met NPCs, quests -- is already a flag, so it comes back with the flags. Monsters come back on a load as on any visit; a half-turned statue ring starts over. Keep it that way: progress that isn't a flag or an autoload field is progress a load throws away.
- **Load order is the point**: `GameState` first (its seed builds the local quests, its flags are the quests'), then `QuestLog` (writes no flags, refreshes nothing), then `Inventory`, whose single `inventory_changed` is what re-reads COLLECT and REACH against the right bag. `GameState.from_save()` doesn't clamp HP; `Inventory.from_save()` refreshes the vitals once the gear that sets the ceiling is back on.
- **A loaded game resumes on the exact spot.** `SceneRouter.resume(map_path, position, facing)` routes like any arrival (`floor://n` or a scene path) with a pending placement; `GameMap._resume_at()` puts the player there unless `can_stand_at()` says the map has changed under it, when the spawn stands, and calms every monster for `Monster.CALM_SECONDS` so one that came back beside you doesn't open the game with a fight.
- **Saving is refused through anything half-done**: `can_save()` wants a player on a map, no input lock (a box, a menu, a fade), no fight, no conversation. An autosave (`request_autosave()`, asked by every map arrival and every floor clear) waits for that moment rather than being dropped. The write goes beside the slot and is renamed over it.
- **A run with no slot saves nowhere** (`SaveGame.slot == 0`): a marathon, a debug `--floor` start, every test and tool. `main.gd` only picks a slot when it is the `current_scene`, which an instanced `main.tscn` never is -- that is what keeps the suite off the player's saves. The save test points `SaveGame.directory` at `user://test_saves`.
- **The file is JSON**, by design: readable, diffable, survives an engine upgrade. Numbers come back as floats (`SaveCodec.whole()` / `plain()`), cell sets are bitmaps over their bounding rect. A missing key loads as a new game has it, so an older save still loads; a renamed item or quest is dropped with a warning; a newer or broken file is refused with the game untouched. Changing the shape of a save: bump `SaveGame.VERSION` and add a step to `_migrate()`. So does changing what a world grows into: version 3 forgets what a version 2 save explored of each floor that is an open field now, since that was another map under the same id.
- `EventBus.game_saved(slot, auto)` / `game_loaded(slot)` are for views (the HUD's "Saved" note). Nothing in the game reacts to having been saved.
- **A new game is an empty save loaded**: `SaveGame.new_game(slot, mode)` runs every autoload's `from_save({})`, so a new game and a save missing everything can't disagree. A field added to an autoload must default in `from_save` to what a new game has. Leaving for the title is `SaveGame.quit_to_title()` → `SceneRouter.leave()`, a fade onto no map that emits `EventBus.title_requested`.
- **The mode is `GameState.mode`** (`STANDARD` / `HARDCORE` / `MARATHON`), saved by name (`MODE_NAMES`; version 1 saves called Hardcore `death_game`, and `_migrate()` renames it). A marathon has `slot == 0` and `save_game()` refuses it outright; `why_unsaved()` says why, for the System tab. A hardcore game can't go back (`can_go_back()`), and **a real defeat asks `SaveGame.end_if_fatal()` before anything else** (`Monster._knock_out`, `BossGate._revive`): true means the game is over and on its way to the title (a hardcore slot deleted, or a marathon's idle avatar being logged out), so the caller does nothing more. A new way to lose a fight must ask it too. While a hardcore game fights, `slot_<n>.fight` sits beside the slot; a save found with it (the game closed mid-fight) is a fight lost -- `load_slot()` refuses it and `bury_fallen()`, which the title calls on opening, deletes it.
- **A marathon is watched for a player who has gone** (`IdleWatch`, autoload; `ui/signal_lost.gd` its view). A marathon is never saved, so leaving the game open would keep it forever: after `IdleWatch.LIMIT` (300 s) with no input -- the window's own `window_input`, heard before anything handles it; a stick under `STICK_DEADZONE` doesn't count -- Cardinal logs the avatar out. The last `WARNING` (60 s) count down on screen (`EventBus.idle_countdown` / `idle_cleared`: a system notice, the world dimming, the avatar flickering); any input stops it. Then every screen closes (`EventBus.screens_close_requested`), a box is cancelled, the avatar shatters into shards of light (`avatar_logged_out`) and `quit_to_title()` says why. Watched only in a marathon with a map up; **nowhere is safe** -- a menu, a box, a fight: a fight waiting on the player is lost on the spot by `CombatManager.forfeit()` (`CombatAction.Kind.FORFEIT`, which `submit()` refuses), and the defeat's `end_if_fatal()` answers true. The clock is the wall clock, so a laptop shut on a marathon wakes up to a logged-out run; tests swap `IdleWatch.clock`.
- **The title screen and the game menu are views** -- see "The game menu". The title only opens on `title_requested`, which `main.gd` emits only as the `current_scene` -- tests and tools never get one. The System tab closes the menu *before* it saves, loads or quits, so the save it makes is one with nothing open.
- **Time played is `GameState.play_time`** (seconds, saved, and in the slot's meta), counted by `main.gd` while a map is up -- not on the title, not between maps. Nothing plays differently for it.

### The game menu, the title and the settings

- **One game menu, five tabs** (`ui/game_menu/game_menu.tscn`): Status, Items, Quests, Map, System. **Esc** opens it on Status, **I** on Items, **J** on Quests, **M** on the Map; **Q**/**E** (or **Shift+Tab**/**Tab**, or a click) change tab, a tab's own key closes it again, **Esc** closes it (after a page's own step back -- out of the settings). Inside it the pages confirm on **Space**/**Enter** -- E is the tab key there -- and the bag drops on **X**. `GameMenu` owns everything the pages share: `can_open()` (a map up, no lock, no box, no fight -- so never over the title), the counted input lock while open, the tab strip and the purse above the window (never overlapping its frame), and the key line; it closes on `combat_began`, and announces itself on `EventBus.game_menu_toggled` so the HUD's vitals, which its tab strip stands on, step aside. The tab keys are read in `_input`, because Godot spends an unhandled Tab on moving keyboard focus and E would reach a page as `interact`. A page is a `MenuPage` (`ui/game_menu/menu_page.gd`): `title()`, `shown()`/`hidden()`, `handle(event)`, `back()`, `hints()` and a `hints_changed` signal. Adding a tab: a page script and a row in `GameMenu.PAGES`/`Tab`.
- **Status** reads `GameState` (bars, totals with what the gear adds, worn gear, floors cleared, time played); **Items** is the bag with the player in their gear -- see the inventory system; **Quests** is the journal; **Map** is the old map screen, `MapPage.status_line()` its header; **System** is save / back to the save / settings / title, with the run's own `SaveCard` beside it.
- **The title is a main menu over the town** (`ui/title_screen.gd`, built in code): Continue (the latest save), New game, Load game, Settings, Credits, Quit, each its own page; Esc goes back a page. **A new game asks how to play first and where second**, since a marathon has no slot to ask about; an occupied slot asks twice before it is overwritten, Delete asks twice. The town behind (`TownBackdrop`) is `town.tscn` instanced and taken apart before it enters the tree -- its tile layers and its NPCs' sprites, dimmed and drifting -- so no `_ready` in it ever runs and nothing about the game is touched; its ground layers sit at z -2, so the title's own ground is at z -10.
- **The menus' pieces**: `MenuList` (`ui/menu_list.gd`) is a column of plates (`MenuRow` / `MenuRowFocus` / `MenuRowLocked`) with the pack's arrow, turned, as the cursor (`MenuList.pointer()`); a row may carry a `value` that left/right step (`stepped`), or be `danger`; a greyed row is still reported. `CardList` lights the card under the cursor (`CardLit`) and leaves the rest in the inset, same margins so nothing moves. `SaveCard` is a slot from `SaveGame.summary()` alone. `KeyHints` draws the key line with the pack's keycaps (`Ui/Input/Keyboard`). The mouse drives the same cursor everywhere.
- **Settings are the machine's, not the run's**: the `Settings` autoload keeps `fullscreen`, `window_scale` (x2-x6 of the 320×180 world view), `text_speed`, `screen_shake` and the two volumes (`music_volume`, `sound_volume`, 0-10 tenths, 0 muting the bus) in `user://settings.cfg`, and `set_value()` applies and writes at once. The dialogue box reads `chars_per_second()` (0 is instant), `BattleStage` reads `screen_shake`, `apply_audio()` sets the buses. A run with no file changes nothing about the window (the volumes are set from their defaults); tests point `Settings.path` elsewhere. `SettingsList` is the one page both the title and System show.

### The dialogue system

- **Flow and view are separate.** `DialogueRunner` (autoload) walks the graph, evaluates conditions, applies effects and holds the input lock; `ui/dialogue_box.tscn` only draws what it is told and calls `advance()` / `choose(i)` back. `test/dialogue_test.tscn` runs the whole system with no box instantiated — if it passes and the game looks wrong, the bug is in the view.
- **A `Dialogue` is an ordered array of `DialogueLine`s**, run top to bottom. A line's `next` jumps to another line's `id`; `&"end"` (`DialogueLine.END`) closes the box; empty falls through to the next array element. Linear conversations therefore need no ids at all.
- **Entry selection is what makes dialogue reactive.** With `start` empty the runner enters at the first *block-opening* line whose conditions pass, so an NPC greets you differently once you've met them or cleared their floor. A line that the previous line falls through into is a **continuation and never an entry point** — without that rule the second half of a gated block becomes a legal opening line the moment its first half's condition fails. Put specific blocks first, end with an unconditional one.
- **`DialogueCondition`** asks `GameState` one small question (`FLAG_SET`, `FLOOR_CLEARED`, `MIN_LEVEL`, `MIN_COL`, each negatable). A line's or choice's conditions are ANDed; for OR, write two blocks. **`DialogueEffect`** sets a flag, grants XP, or emits `EventBus.item_granted` / `quest_started` / `col_granted` / `col_charged` — dialogue never calls Inventory or QuestLog, so it works before they exist.
- **Locked choices** either vanish (`hide_when_locked`, the default) or stay visible and greyed with a `locked_hint` — "(not until Illfang falls)". The runner refuses out-of-range and locked indices as well as the UI, since it is the one place that must not be talked into an impossible branch.
- **Two entry points, one pipeline**: `DialogueRunner.start(dialogue)` for conversations, `EventBus.message_requested` (→ `say()`) for unbranching text from chests, signs and system notices. A conversation started while one is open is queued, not dropped.
- **`Npc.dialogue` beats `Npc.lines`**; `lines` stays for extras who say one thing. `met_flag` is set *after* the conversation, so a first-meeting block can still see "we haven't met". `hidden_until` keeps an NPC off the map -- not drawn, not solid, not offered, not marked on **M** -- until a flag is set, then fades them in, as a sealed chest does. **Anything that appears in play turns solid only once the player is off it** (`SolidWhenClear.attach($Solid)`): a wisp's chest appears a cell below its shrine, exactly where you stood to watch it go in, and made solid at once it boxed you in against the lantern.
- Adding a conversation: a `.tres` in `resources/dialogue/`, then point an NPC's `dialogue` export at it. Hand-writing one is fine — note that typed arrays serialize as `Array[ExtResource("choice")]([SubResource("...")])`, and sub-resources must appear before the resources referencing them.

### The inventory system

- **Two signals, one direction each.** `EventBus.item_granted` is the world saying *"here, have this"* — combat loot, a chest, a dialogue reward — and `Inventory` is its only listener. `EventBus.item_added` is Inventory replying *"it is in the bag"*, and that is what UI and (in M5) quest objectives listen to. Keeping them apart is what stops a full bag from silently reporting success, and what stops `add()` from re-triggering itself. **Nothing outside `Inventory` should emit `item_added`.**
- **Flow and view are separate**, same as dialogue and combat. `Inventory` (autoload) owns the bag; the game menu's Items tab (`ui/game_menu/items_page.gd`) draws it and calls `use()` / `equip_stack()` / `drop_stack()` back. `test/inventory_test.tscn` runs the whole system with no screen instantiated.
- **Gear reaches combat through `GameState` and nowhere else.** Worn bonuses are summed by `Inventory.bonus()` and folded into `GameState.total_attack()` / `total_defense()` / `total_speed()` / `total_max_hp()`; `Combatant.from_player()` reads those. A sword is `+6 attack` by the time combat sees it — **never** add an item lookup to `CombatMath` or `CombatManager`. The bare `GameState.attack` fields are *base* stats; don't read them directly.
- **Equipment leaves the bag when worn.** A slot is a place, not a flag, so the bag count is the truth and unequipping into a full bag is refused rather than quietly deleting a sword. Equipment also never stacks: three swords are three slots, so any one of them can be worn without splitting a pile.
- **`remove()` is all-or-nothing.** Asking for more than there is removes none of it and returns 0 — a caller that spends three and silently gets two taken has a corrupted bag and no way to notice.
- **Consumables are percentages of max HP, never flat points**, for exactly the reason statuses are: a flat 20-point potion is everything on floor 2 and nothing on floor 90.
- **Statuses live on a `Combatant`, so field use can only heal.** An item whose only effect is `applies` declares `usable_in_field = false` and `Inventory.use()` refuses it. In battle it is `CombatManager` that applies the effect; `Inventory.consume()` only empties the bottle.
- **Slot order is bag state, not a view preference.** `Inventory.move_stack(from, to)` is what the screen's drag-and-drop calls, and it decides between merge (same item, target has room), move-to-the-back (target past the last used slot — the bag is a compact list, so every empty slot is the same place) and swap. The screen greys out exactly what `move_stack` would refuse, because it asks the same predicates it paints with.
- **The mouse drives the keyboard's cursor, not a second one.** Hovering a slot *is* selecting it, so there is no moused-over state to keep in step with the arrow-key one. Drag-and-drop goes through `Control.set_drag_forwarding` so slots stay plain `Panel`s and every rule lives in `items_page.gd`; `tools/screenshot.gd` drives a real drag with synthesised mouse events, which is the only way to see the drop-target highlighting.
- **A chest checks `Inventory.fits()` before opening.** Opening is irreversible and the opened-flag would outlive the item it destroyed.
- **The bag's filter is a view of the bag, not a second order.** The category tabs show a subset of `Inventory.stacks()` in bag order; a drop on another stack moves by its real index, and on an empty cell is "the back of the bag" -- refused when the bag is full, since a filter shows empty cells a full bag hasn't got. **The comparison is the autoload's**: `Inventory.change_if_worn(stack, stat)` (what wearing that copy would change against what is worn), drawn as green/red differences under the player.
- Adding an item: a `.tres` in `resources/items/`, an id in `ItemLibrary.ITEMS`, and an icon: a row in `tools/build_item_icons.gd`'s `ICONS` (a pack sprite, or a table in `DRAWN`), then run it. The inventory test will fail if a loot table, chest pool or dialogue effect names an id with no resource behind it, or an item's icon isn't its 16x16 tile.

### The economy (Col)

- **The purse lives in `GameState`** (`col()`, `can_afford()`, `spend_col()`), beside XP, so `MIN_COL` is a `GameState` question like every other condition. Same two-signal shape as items: `EventBus.col_granted` is the world paying (a kill, a chest, a quest, a sale) and `col_charged` a dialogue line costing money — requests whose only listener is the purse — and `col_changed` is the purse's reply. **Nothing else emits `col_changed`.** Spending is all-or-nothing.
- **Income is linear, like XP and for the same reason.** `EnemyType.col_reward`/`col_growth` default to `FloorTuning.KILL_COL`/`KILL_COL_GROWTH`; bosses carry `Bestiary.BOSS_COL`. `CombatManager._end` grants it with the XP, deterministically. A chest's Col is `FloorTuning.chest_col(floor, tier)` (plain / gilded / sealed), read when the lid opens (`Chest.col = -1`) — **never rolled**, so adding it moved no floor's rng. Quests pay Col with `GIVE_COL`; a settled floor's job pays its monsters' worth, drawn from nothing.
- **Prices are the item's, not the shop's**: `Item.price` (fixed on every floor) and `Item.shop_floor` (the floor `GameState.highest_floor_reached()` must reach before any shelf carries it; 0 = found, never sold). Selling pays `sell_price()`, half; key items never sell, worn gear isn't in the bag to sell. Stock climbs, prices don't — a percentage potion stays worth buying and simply gets cheap.
- **A `Shop` (`resources/shops/`, listed in `ShopLibrary`) is only a list of wares** plus the rules: `stock()`, `refusal()`, `buy()` (shelf, purse and bag all checked before anything moves), `sellable()`, `sell()`. `ui/shop_screen.tscn` draws it and greys exactly what `refusal()` refuses. A shopkeeper is an `Npc` with `shop` set: talking opens the counter via `EventBus.shop_requested`. Adding one: a `.tres`, an id in `ShopLibrary.SHOPS`, and an NPC table row with `"shop"` (authored floors) — the inventory test checks every ware and every hub's counter.
- **A village's counter is its band's** (`ShopLibrary.village_shop(biome)` → `village_<biome>`): the first `ShopLibrary.SPECIALITIES` wares are the band's own -- a wearable sidegrade and a consumable, sold at no other counter, `shop_floor` no later than the band's first village can stand (its floor + `SETTLE_AFTER`) -- and the rest are staples sold elsewhere too. Sidegrades, not required power: each trades one stat for another, so the gates never turn into errands. The keeper is the floor's (`LocalQuests.trader(n)`, on `hash("<seed>:trade")`, a settler's name no giver or lost player on the floor has), set on a duplicate of the shop. The inventory test holds every band to all of that.
- **The smith's +N is per copy, on the `ItemStack`** (`plus`): equipment is a stack of one, and a worn slot holds the stack itself (`Inventory.worn(slot)`), so the enhancement goes on and comes off with it. `equip(item)` wears the best copy, `equip_stack()` a chosen one; `remove()` takes the least enhanced; the shop sells a chosen stack (`sell_stack()`). It reaches combat only through `Inventory.bonus()` → `GameState.total_*()`. The rule is the item's (`max_plus()` by rarity, `enhanced_stat()`, `plus_step()`), the forge's is `Smith`'s (`cost()`, `tier()`, `odds()`, `attempt(stack, extra, roll)`): a quarter of the price per level, n+1 materials of a tier, odds falling from 100%, +10% an extra, a failure costing what went in and nothing else. Nezha opens it from his menu with `DialogueEffect.OPEN_FORGE` (→ `EventBus.forge_requested`); `ui/forge_screen.tscn` waits for the box to close and ignores **E** for `Player.INTERACT_GRACE`. A forge is a `.tres` in `resources/smiths/` plus an id in `ShopLibrary.SMITHS`. The save keeps every stack's `plus`, worn ones included.
- **Argo sells doors** (`DoorIntel`): `DialogueEffect.SELL_INTEL` queues a conversation built in code — MIN_COL-gated choices that `TAKE_COL` a floor's hunting (`kill_col × monster_count`) and set `boss_found_<n>` — for floors visited, not cleared, door not found, never floor 1. **She sells the location, not the way**: `GameMap._chart_found_doors()` charts a found door's room on **M** when the floor is built; the labyrinth stays unexplored.
- **The peddler** (`FloorGenerator._add_merchant`): on ~40% of generated floors (`hash("<seed>:merchant")`, never the floor's rng) an `Npc` keeping the `travelling_merchant` shop stands in the safe zone, by rule on the middle of a side against a maze pillar, never in a doorway. The floor test's `_audit_merchant` walks the room with it and the fire solid.
- **The dropped purse is one pile** (`GameState.drop_col()` / `dropped_col()` / `recover_col()`): a real defeat — not a flight or a stalemate — calls `GameMap.player_fell()`, which drops everything where the player stands and loses the previous pile. `GameMap` puts a `DroppedCol` pouch (not solid) wherever the pile is, on arrival and as it falls; `EventBus.col_dropped` with amount 0 retires it. The save keeps both.

### The combat system

- **Flow and view are separate**, same as dialogue. `CombatManager` (autoload) owns the turn loop, targeting, statuses, AI and the input lock; `ui/battle_hud.tscn` (the menu) answers with `CombatManager.submit(action)`, and `BattleStage` on the map draws what it announces; `BattleHud.aimed` is how the menu's target cursor reaches the stage. `test/combat_test.tscn` fights hundreds of battles with no screen instantiated — if it passes and the game looks wrong, the bug is in the view.
- **Items are a combat verb.** `CombatAction.Kind.ITEM` resolves through `_resolve_item()`: it costs the turn but no cooldown and no post-motion, only ever lands on your own side, and spends the item whether or not it healed for full value. `submit()` re-checks the bag, because it can empty between the menu being drawn and the answer arriving.
- **`CombatManager.start(encounter)` is awaitable** and returns a `CombatResult`. That object is all a caller needs: `BossGate` clears the floor on `victory`, a `Monster` frees itself. XP and loot are already granted by the time it arrives.
- **`submit()` is the only door in, and it refuses illegal moves** — a skill on cooldown, an out-of-range target, fleeing a boss. The UI greys those out too, but the runner is the one place that must not be talked into an impossible move. **It must also accept a synchronous answer**: a caller that submits during the `command_requested` signal is answering before the loop parks, which is why the accepted action is held in `_pending` rather than delivered by signal alone.
- **Everything a combatant can do is a `Skill`**, including the plain attack (`SkillLibrary.basic_attack()`). There is no separate enemy-attack path that can drift from the player's.
- **`Combatant` is runtime-only** and dies with the fight; `write_back()` is the single path back into `GameState`, and only the player uses it. HP carries in and out — there is no free heal at the door. Stats come in through `GameState`'s `total_*` accessors, which is where equipment folds in.
- **A fight is drawn on the map it happens on.** Whoever starts it -- `Monster._engage()`, `BossGate._step_out()` -- asks the map where everyone stands (`GameMap.stage_battle()` / `boss_formation()`) and announces the `BattleField` on `EventBus.battle_staged` just before `CombatManager.start()`; `BattleHud` puts a `BattleStage` on the map for it, which pairs `field.enemy_nodes[i]` with the encounter's enemies by index. The stage steps everyone into formation -- the player moved by `position`, never `move_and_slide`, so only to a cell the solver proved their body fits -- makes its own `Camera2D` current and eases it in (`BattleStage.ZOOM`, ×2, where `fits()` says the fighters, the pointer and the menu band fit; ×1 where they don't), fades bystanders, lights a pool of line of sight in the `Darkness`, and plays every report on the real sprites: the lunge, the report *landing* at the far end of the step, the skill's `SkillFx`, the flash, numbers, enemy bars, a whole-unit camera shake on a crit or stagger, the pack's smoke on a death. All view-only, and skipped when `step_delay` is 0. On `combat_finished` the camera eases home and the stage frees itself. `Encounter` carries nothing about the place: `CombatManager` still never learns what a map is. To look at it: `tools/screenshot.gd` fights in a room, a field corridor and a dark passage (`05`–`07`), every authored boss and a generated one with its escort (`08`), and one monster per band (`09`, also side by side on `09_bands_sheet.png`).
- **A fight with no field is `BattleHud`'s plates over the map and nothing else** -- what a test or tool gets from a bare `CombatManager.start()`. In play it can't happen: the floor test's formation sweep proves a formation from every cell a monster can catch you on and every cell a door can be challenged from. Don't bring back a screen to catch it; fix the solver.
- **All balance lives in three places**: `CombatMath` (the formulas), `FloorTuning` (the 100-floor curve), and the `.tres` files (per-enemy stats). Never tune inside `CombatManager`.
- **Mitigation is `attack / (attack + defence)`**, not subtraction and not a fixed curve. A ratio holds its shape whether the numbers are 8 and 4 or 240 and 130; the other two break at one end of a 100-floor climb. `test/combat_test.gd` asserts this directly.
- **The XP curve is linear** (`GameState.XP_BASE + XP_STEP * (level - 1)`) because monster payouts are linear in their level. Making one exponential without the other stalls the climb around floor 17 — measured, not theoretical.
- **Statuses are percentages of max HP, never flat points.** A flat 4-damage poison is everything on floor 2 and nothing on floor 90.
- **A skill's look is data like its numbers.** `Skill.fx` names a `SkillFx` (`resources/fx/`: one of the pack's effect sheets, its frame count and timing) that `BattleStage` plays over whoever it lands on; `EnemyType.strike_fx` overrides how a monster's *plain* attack looks (a boar claws), so the attack itself stays the one `basic_attack()`. `Skill.icon` / `icon_disabled` are the menu row's two drawings, `StatusEffect.emote` the pack's speech bubble shown over the head that wears it. Combat never reads any of them.
- Adding an enemy: a `.tres` in `resources/enemies/`, a sprite entry in `gen_placeholder_art.py`'s `BATTLERS`, and an id in `Bestiary.ENEMIES` + the relevant `BIOME_POOLS` row. Adding a skill: a `.tres` in `resources/skills/` with an `fx` (and, for the player's, both icons) plus a line in `SkillLibrary.PLAYER_SKILLS` (enemy skills are referenced by their `EnemyType` and need no registry); a status needs an `emote`. The combat test refuses any of those missing.
- **A duel is a rule of the runner, not a different fight** (`Encounter.first_strike`): every combatant yields at half the HP it came in with, no strike takes anyone below 1 while it lasts, and it ends the moment one side is there -- `CombatResult.victory` or `yielded` (not a defeat), `duel` set, and no XP, Col or loot. `Encounter.betrayal` (a `Skill`, the rigged duel's paralysis pick) turns the moment it is decided into a refusal (`CombatReport.Kind.YIELD` with `success` false) and that skill on the player; from there it is an ordinary fight to the end, with rewards, and `CombatManager.can_flee()` lets you run (the HUD asks it, not the encounter). The duellist is a player on the player's own stat curve, at `Bestiary.DUEL_LEVELS` over the floor's monsters; the combat test measures honest and rigged duels on four floors.
- **Bosses have HP bars** (`BossPhase`, `scripts/resources/boss_phase.gd`). `EnemyType.phases` lists the bars after the first; `bars()` is one more, and **the HP is shared between them, never added** (`Combatant.from_enemy` divides `hp_at()`), so a phase moves no boss's total. `Combatant.take_damage()` emptying a bar with another behind it fills that one at once (what was left of the blow is lost, as SAO's bars lose it) and marks it `breaking`; `CombatManager._settle()` starts every breaking bar's phase first (`_break_bars()` → `Combatant.enter_phase()`): no statuses, no stagger, poise whole, then whatever the phase sets -- `display_name`, `form` (an `EnemyType` read for its art and `strike_fx` only), `skills` (replacing the last bar's, keeping `Bestiary.BOSS_SKILL`), `skill_bias`, stats scaled off what it came in with, a `buff`, an out-of-turn `opens_with`. It reports a `CombatReport.Kind.PHASE` (the `phase` on it), then shows the phase's `interlude()` -- `narration` with no speaker, `lines` in `speaker`'s voice, `{player}`/`{level}`/`{floor}`/`{hours}`/`{minutes}`/`{seed}` filled from `GameState` -- **through `DialogueRunner`, only when paced**: an unpaced fight (a test, a tool) has nobody to read to, and the box would wait forever. The stage flares the boss white and `FoeFigure.become()`s its form, pips under its bar count the bars behind it, `BossPhase.music` changes the fight's track (`Audio` hears the report), and `BattleHud` steps its message line aside while the box is up. **The formation makes room for the biggest shape first** (`FoeFigure.body_of` over `EnemyType.forms()`), so a boss that grows mid-fight never grows into you -- the floor test's boss sweep covers it. The AI picks a self-buff (`STATUS`, `SELF`) it isn't wearing as it would a swing. A test's "weakest first" means least *total* HP (`max_hp * bars`), or a boss's bar looks weaker than its escort. Illfang fights on four, drawing the nodachi on his last.
- **Boss escorts are capped at one** in `Bestiary._escort_count` *because the party is one*. Two full-strength escorts against a solo player measured at ~1 win in 20 on floor 100. Lift the cap when the party grows, not before.

### The quest system

- **The whole system is one autoload plus six signal handlers**, because every input a quest needs was already being announced by the time it was built: `quest_started` → `start()`, `enemy_defeated` → KILL, `inventory_changed` → COLLECT, `dialogue_finished` → TALK, `floor_cleared` → REACH, `quest_turn_in_requested` → `turn_in()`. **Nothing in combat, inventory, dialogue or the floor system knows `QuestLog` exists.** That is the payoff of the event bus, and it is why quests landed without touching any of them.
- **Quest state is mirrored into `GameState` flags** — `quest_<id>_started`, `_ready`, `_done`. That one decision is what lets an NPC gate a line on a quest, a quest gate itself on another quest, and (later) a chest open only for a quest-holder, all through `DialogueCondition`'s existing `FLAG_SET` test. `DialogueCondition` still only knows about `GameState`, so there is one condition language in the game rather than two that drift. Use `QuestLog.flag_for(id, suffix)` rather than building the string.
- **Prerequisites are `DialogueCondition`s and rewards are `DialogueEffect`s.** Not laziness: a prerequisite asks `GameState` exactly the questions a dialogue line asks, and a reward does exactly what a dialogue effect does — so a quest can pay out by starting another quest for free. They are misnamed for the second job; renaming them would rewrite every dialogue `.tres` for a word.
- **Counted objectives vs. read objectives is the one real decision in the data model.** KILL and TALK are *counted* when they happen, because nothing else remembers a kill. COLLECT and REACH are *read* from the bag and the cleared-floor list, and are recomputed from scratch whenever either changes. So **a collect objective reads the bag; it does not count deliveries** — counting `item_added` would let a player satisfy "bring me five hides" by picking five up and throwing them away, and the objective could never go back down. `QuestObjective.is_state_based()` is that distinction and `QuestLog` is what acts on it.
- **Ready is a state, not a completion.** `needs_turn_in` (the default) parks a quest at `READY` with its `_ready` flag set until the player goes back and says so, which is what a turn-in dialogue branch reads. Ready must be able to come *back off* — spend the hides you were asked for and the quest is not ready any more, or the turn-in fails on arrival. Set `needs_turn_in = false` only when there is nobody on the other end of it.
- **Turn-in re-checks two things rather than trusting them**: the collect items, because the bag can empty on the walk back; and room for the reward, because a quest that pays into a full bag has destroyed what it paid. The room check runs *before* the items are spent, so it is conservative — it can refuse a turn-in that would in fact have fitted once three hides left the bag, and it says so rather than silently eating an Anneal Blade.
- **`turn_in()` closes the quest out before spending the collect items.** Spending them emits `inventory_changed`, which comes straight back as a COLLECT refresh, and a quest still in `_active` at that moment gets its progress reset on the way out the door.
- **The offer and the prerequisites must be gated on the same conditions.** This is the one failure mode the arrangement can produce: a dialogue choice offering a quest `QuestLog.start()` would refuse, so the player picks "I'll take it" and nothing happens. The quest test asserts this directly for both of Argo's offers.
- **Flow and view are separate**, same as everything else. `QuestLog` owns state; the game menu's Quests tab (**J**, `ui/game_menu/quests_page.gd`) and `ui/quest_tracker.tscn` draw it; `test/quest_test.tscn` runs the whole system with neither instantiated. In the journal the cursor arrow is where the player *is* and colour-plus-glyph is what the quest *is* — never both on one cue, or the selected row and the ready row become indistinguishable.
- Adding a quest: a `.tres` in `resources/quests/`, an id in `QuestLibrary.QUESTS`, and a dialogue branch that offers it (plus one that takes it back, if it needs turning in). `QuestLog.accept(quest)` takes a resource directly for anything that isn't shipped content — the library is a lookup, not a gatekeeper, but the rules still live in the log.
- **A settled floor's jobs are named, not stored.** `local_<floor>_<kind>` (`hunt` / `gather` / `lost`) is the whole quest: `QuestLibrary` hands any `local_` id to `LocalQuests.build()`, which draws everything -- which two jobs, giver, target, count, pay, words -- from `hash("<seed>:settle")` and the floor's bestiary, never the floor's rng or the map, so the journal can draw a floor-7 job on floor 60 and the save stores only ids. Its prerequisite is `FLOOR_CLEARED n+3`, the condition the settler's offer is gated on. The settler's conversation and the lost player's (`local_<n>_lost_found`, the one TALK target with no `.tres`: `QuestObjective.target_is_valid()` asks `LocalQuests.is_conversation()`) are built in code. Pay is a few of the floor's monsters' worth of XP plus an item -- on top of the curve, never a second one. The lost player waits in a free labyrinth dead end, `Npc.hidden_until` the job's started flag (not drawn, not solid, not offered), and isn't placed once the job is ready or done. A new template is an entry in `LocalQuests.KINDS`/`TEXT` and a branch in `build()`; the quest test's sweep covers it on every floor.

### Roaming monsters

- **A `Monster` is still an `Interactable`, and now it moves.** Wander (a leash round its spawn point) → notice (`AGGRO_RADIUS` plus a raycast on layer 1) → chase at `CHASE_SPEED` 62, *below* the player's 90 → give up past `LOSE_RADIUS` / `LEASH_RADIUS` / a second out of sight → walk home. Contact is its `Contact` area overlapping the player's body, not a keypress; pressing **E** is still a way in.
- **It has no solid body.** It steps by asking the physics space whether its probe fits (`_free_at`), sliding per axis, so it respects walls while nothing can collide with *it*. That is what keeps "a monster can never wall off a corridor" true and keeps it out of the floor test's flood fill. Don't turn it into a `CharacterBody2D`.
- **Who struck first is `Encounter.opening`.** E on a monster that isn't chasing → `PARTY_FIRST`; run down facing away → `ENEMIES_FIRST`; otherwise `NORMAL`. `CombatManager` only honours it in round 1 (`_turn_order()`) and announces it with a `CombatReport.Kind.OPENING`. **The monster decides, combat never learns what a map is.** Bosses stay `NORMAL`.
- **Nothing engages through the input lock** — the monster freezes entirely while it is held. After a fight it survived, it is `STUNNED` for `GRACE_SECONDS` and then walks home ignoring the player; after *any* fight, every monster is calm for `CALM_SECONDS`, so winning one never drops you into the next. Keep it longer than `BattleHud.OUTRO_TIME` plus the stage's camera ease home: the result is still up while the player can already move.
- Wandering uses the global RNG on purpose: behaviour, not generation. Nothing about a floor's seed depends on where a boar drifted.
- The base viewport is 640×360 and the player's camera sits at zoom 2 (`UiLayout.WORLD_ZOOM`): 320×180 of world on screen, with the UI laid out at twice the map's pixel density (see "The UI and the pack"). Anything else that frames the world -- `BattleStage`'s camera, the title's `TownBackdrop` -- multiplies by `WORLD_ZOOM`. The floor test refuses an authored map smaller than one view, because `Camera2D` resolves limits tighter than the screen by pinning right/bottom and showing the void top-left.

### The floor system

- **`FloorDefinition`** (`.tres`) describes a floor. If it has an `authored_scene` it's hand-built; otherwise it's generated. `FloorRegistry` returns one for any floor 1–100, synthesising non-authored ones from the biome band table + `FloorTuning`.
- **`FloorRegistry.build_floor(n)`** is the single entry point — it hides which kind you got. `SceneRouter.enter_floor(n, spawn)` is what gameplay calls.
- **`FloorGenerator`** builds a field of rooms + L-corridors and a labyrinth beside it, and returns *the same node shape as an authored map* (`Ground` / `Walls` / `SpawnPoints` / `Player` + interactables). Keep it that way: `GameMap`, the camera and the router all depend on that shape and on nothing else.
- **The labyrinth is a strip of its own on a seeded side of the field**, never a corner of it: the field stays a rectangle, and an L-corridor between two points stays inside their bounding box, so no field corridor can cut into the maze. `FloorDefinition.size` is the *field*; `labyrinth` (from `FloorTuning.labyrinth_cells`) adds the strip, so a generated map is bigger than `size` — read its bounds off `Walls`, not the definition. The maze is usually *longer* than the field's side (12×7 cells on floor 2, several screens each way, because one that fits on a screen is read from outside): along the shared side the shorter of the two slides along the longer and rock fills the rest. Maze cells are a two-wide passage and a two-thick wall, because that is what every biome's walls can draw. The maze is perfect and the boss room is one of its leaves (the walk marks the whole block visited on entering it), which is what makes "the door shows from inside" mean "you solved the maze". It is regrown from the same seeded stream until the walk to the door is long enough and it has dead ends: grid distance is a poor guess at walking distance. The generator leaves `labyrinth`, `labyrinth_mouth` and `boss_room` as metadata on the map, for the tests and nothing else.
- **A generated floor has a shape** (`FloorDefinition.Shape`, decided per world by `FloorRegistry.shape_of(n)`): **classic** -- the field and its labyrinth, above -- **open field** or **dungeon** (`FloorRegistry.BUILT_SHAPES` lists what is built; a shape picked but not built builds classic). The pick is its own stream (`hash("<seed>:shape")`), about 60% classic (`SHAPE_CLASSIC`), never the same new shape two floors running, floor 2 and the top floor always classic -- so adding a shape moved no classic floor: fingerprint them all, each floor in its own process, before and after any change to it (a floor generated after another can differ in its people's names, in HEAD as much as anywhere). `FloorGenerator.shape_override` forces one for tests and tools. **An open field** has no labyrinth and no dark: a field half as big again (`FloorTuning.open_field_size`) of bigger clearings (`open_room_count`, `CLEARING_W/H`), and the boss in an **arena** -- `ARENA_ROOM` walled round, on a strip of its own on a seeded side like the labyrinth's (`_place_strip`, shared), its door in plain view. Its gate is a `SealedDoor` (`ArenaSeal`) with `opens_itself`, whose hollows are the **waystones** (`Waystone`, `scenes/world/waystone.tscn`) in the clearings farthest from the arrival and each other: **E** wakes one (`waystone_<n>_<i>`), and the last breaks the seal from wherever it stands, setting `arena_<n>_open` and `boss_found_<n>`. The clearing nearest the gate is the floor's safe zone, its fire placed by rule off every corridor. Where things stand is rule, not rng (`_plan_arena_field`); the puzzles keep clear of them (`FloorPuzzles.keep_clear`). Nobody is lost on an open field (`LocalQuests` drops the job), Argo sells no arena, and the camp's people talk about the arena (`FloorCamp.open_field`). The floor test's `_audit_arena` walks it shut and open.
- **A dungeon is several maps** (`DungeonGenerator`, extending `FloorGenerator` for its helpers; `generate()` hands it a dungeon by path, since naming the subclass would be a cycle). `FloorTuning.dungeon_levels(n)` levels (3-5), each rooms and corridors with a **chamber** on a strip of its own (the arena's code): a stair chamber whose doorway holds a `SealedDoor` (`StairsSeal`, `opens_itself`) and whose north wall the **ladder up** stands against, or on the top level the boss hall, lit, its door `found_on_arrival`. **Level 1 is the floor's own map** -- `floor://n`, `floor_n`, the floor's seed -- so gates, defeat, debug starts and old saves land on it; level s is `floor://n/s` / `floor_n_s` from `DungeonGenerator.level_seed` (`SceneRouter.floor_path`/`floor_at`, `enter_floor(n, spawn, fade, level)`, `FloorRegistry.build_floor(n, level)`/`levels_of(n)`). Stairs are `FloorStairs` with `target_level`: up to the next level's `stairs_down` spawn, down to the last's `stairs_up` (the foot of its ladder). **What seals a level** (`Seal`, from the floor's `hash("<seed>:seals")`, never the same twice running, falling back braziers → statues → levers → warden where it doesn't fit): a **warden** (a `Monster` with a `defeat_flag`, which keeps it beaten), two **levers** (`lever.tscn`: the `Waystone` script, other art and words), or a brazier rite / statue ring pinned by `FloorPuzzles` with a per-level `flag_prefix` and `with_chests = false`. A dungeon has no side puzzles. Level 1's arrival room is the camp's plot, **lit** (`GameMap.lit_areas` → `Darkness.clear()`); every level is otherwise dark. The middle level (`landing_level`) has a fire in a room, a safe zone. The floor's monsters and chests are shared between the levels below the top (`share_of`), monsters drawn again rather than dropped, so the floor carries its full count; the top has none. Nobody is lost in one and Argo sells none (both ask `!= CLASSIC`). Save version 4 forgets what was explored of a floor that is a dungeon now. The floor test's `_audit_dungeon` walks every level.
- **A generated floor may have a modifier** (`FloorModifier`, `scripts/world/floor_modifier.gd`; picked by `FloorRegistry.modifier_of(n)` on its own stream, `hash("<seed>:modifier")`, `FloorModifier.CHANCE` of generated floors, never authored, floor 2 or the top; `FloorGenerator.modifier_override` for tests and tools). **Infested**: `FloorTuning.infested_count(n)` monsters on top of the count, placed by `FloorGenerator._add_swarm()` from `hash("<seed>:infested")` *after* the floor's own and before the puzzles (which step them off a piece as they do any monster), named `Swarm<i>`. **Storm**: only where the band has weather (`FloorModifier.WEATHER`) and never a dungeon; `GameMap.notice_scale` (`FloorTuning.STORM_NOTICE`) shortens `Monster._notices`, and a `Weather` node (`scripts/world/weather.gd`, view only, at z 9 just under the `Darkness` so the dark hides the storm too, following the current camera) draws it, the map's modulate tinted by `Weather.tint()`. Both are added by `_mark_modifier()` once the floor is built, so **a modifier moves nothing**: fingerprint every floor with `modifier_override = NONE` against HEAD after any change to it. Every arrival emits `EventBus.floor_announced(title, line)` -- empty for none, which takes the HUD's headline down -- the region reads "<biome> - Rainstorm", the gate menu names it, and the camp's scout adds `FloorModifier.camp_line()` as a continuation of their opening. Nothing is saved: it grows from the world seed. The floor test's `_audit_modifier` builds every modified floor with and without it.
- **Every labyrinth has a safe zone on the way to its door** (`FloorGenerator._place_camp`): a 2×2 block of maze cells opened into one 6×6 room, as near the middle of the walk as the maze allows. Only a block the maze already joins internally (three links inside) qualifies, so the maze stays perfect; a maze with none on the way is regrown like a short one. A `Campfire` (`scripts/world/campfire.gd`) stands where the block's pillar was and rests you to full on **E**. `GameMap.safe_zones` (cells) is the rule, not the fire: a `Monster` won't step in (`_free_at` tests its probe's width) and ignores a player inside (`_sheltered`); `Darkness.glow` keeps the room half-lit once seen. The generator leaves `safe_zone` metadata for the tests.
- **A trap is always a gilded chest, never the reverse.** `Chest.gilded` is the tell, `Chest.trap` (`ALARM` / `TELEPORT`) what it does, decided by the generator from the floor's rng (field chests only -- the labyrinth's dead-end chest is never gilded). It springs after the item is in the bag. An alarm spawns `Chest.ALARM_PACK` ordinary `Monster`s round the chest (global RNG -- behaviour, not generation); a teleport waits for the box to close and moves the player inside `SceneRouter.blink()` to `trap_target`, a labyrinth dead end. The floor test refuses a trapped plain chest and a teleport onto anything but reachable labyrinth floor.
- **A `BossGate` with a `reveal_area` is hidden** — no sprite, no collision, `is_available()` false — until the player's body enters that rect; then it sets `boss_found_<n>` and fades in. Found stays found (so does cleared), because losing already costs the walk back. Authored floors hide theirs the same way, in their labyrinth's boss room.
- **Fog of war decides what is explored, not what is drawn — except inside a labyrinth**: everywhere else the screen shows everything in camera as always. Inside `GameMap.dark_area` (the generator sets it to the labyrinth's rect) a `Darkness` node covers what the same visible set leaves out — near-black where never seen, dimmed where explored — one texel a cell, linearly filtered and faded, at `z_index` 10 over props and monsters; monsters in the dark get alpha from `Darkness.light_at()` so a remembered passage doesn't show who is in it. The camera sees over walls, so without this a maze is read from outside. `GameMap` asks `FogOfWar.visible_from()` on each new cell — radius 7, a straight line not crossing a wall — and stores the result in `GameState` per map id (`explore()` / `explored_cells()`), plus the part of it within `WALK_REACH` as *walked* (`walk()` / `walked_cells()`); the save keeps both, as bitmaps (`SaveCodec`). Water collides, so it lives on `Walls`; `GameMap.is_water()` tells it from rock by its terrain (or, undressed, its slot), and the floor test checks that on every band, since a misread leaves the far shore of every pond unexplored.
- **`MapDresser.open_cells()` and `lay_into()` are the exceptions to "dressing runs last"**. `lay_into()` lays a landmark into a dressed room -- boulders cleared, water, path and invisible footprint painted -- and re-picks only the water and ground within a cell of what changed, taking the flowers off it, so a floor with a landmark is dressed exactly as the floor without outside its room (painting before `dress()` would have shifted every flower after it in reading order). `open_cells()` is a cracked wall broken in play. It paints the opened cells plain floor and re-picks only the ring round them by nearest match (the blob is a complete 47, so every cell finds its exact tile and nothing further changes), and in a forest `step_trees_back()` lifts the trees off them and covers the edge it bared, never hanging a crown over the cells it was told to keep clear. Anything that reshapes a played map calls `GameMap.reshaped()` after, which drops the cover cache and looks again from where the player stands.
- **`MapDresser.dress()` dresses the finished layout, and it runs last** — called by `FloorGenerator` and by `authored_floor.gd`'s `_join_walls()` alike, so a built floor and a generated one follow one rule. It is a pass over the finished layout, not a step in building it: carving, decor and the reachability check all happen against plain slot tiles, so the layout can never depend on which tile a cell ended up drawing. A BLOB biome's wall mass is autotiled — only cells still holding `wall_tile` join (decor on the same layer carries no terrain, so the mass draws an edge against a boulder), and `ignore_empty_terrains` must stay `false`, since a carved cell has no terrain and those are precisely the neighbours an edge tile is chosen against. A biome whose `wall_terrain_set` is -1 ships flat. Forest walls, ground and water are under "Map dressing and the art pack".
- **Determinism is a requirement, not a nicety.** Seeds come from `FloorRegistry.seed_for(n)` = `hash(world_seed, floor_number)`. Never use unseeded `randi()` in generation — it breaks save consistency and makes bugs irreproducible.
- **Puzzles are `FloorPuzzles`' (`scripts/world/floor_puzzles.gd`), on their own seeded stream** (`hash("<seed>:puzzles")`), never the floor's: asking the floor's rng for anything new reshuffles every generated floor and every number measured on them. `FloorGenerator.with_puzzles = false` builds the floor without them and the floor test proves it is the same floor. Two passes: `plan()` on the finished layout before `dress()` (it carves the vault, so its walls join like any), `place()` once the floor's chests exist. A piece that lands on a monster steps the monster off its cell rather than dropping it -- the monster count is the boss's balance. **Solved is a flag** (`puzzle_<n>_wisp` / `_braziers` / `_statues` / `_vault` / `_crack`) and everything that reacts -- a shrine lighting, a sealed chest appearing, a door's hollow lighting -- listens for `EventBus.flag_changed`; nothing in a puzzle knows its reward exists. **Sealed is the third chest tier**: never trapped, `hidden_until` its puzzle's flag (not drawn, not solid, not offered), the floor's best loot (`SEALED_LOOT`). Sigils are flags a chest sets as it opens (`Chest.sigil_flag`); the `SealedDoor` is a solid node in a carved doorway, not wall, so the flood fill reaches the vault either way. A `BrazierRite`'s clock stops while the input lock is held. A puzzle with several pieces has one `Node` that owns the rule (`BrazierRite`, `StatueRing`) and pieces that only know their own state (`Brazier.lit`, `Statue.facing`); a ring of four statues has exactly one answer for any arrangement (the turning matrix is invertible mod 4), so `StatueRing.turns_to_solve()` is a brute force over 256 and the scramble is turning it backwards. **A cracked wall carves nothing**: its doorway and hollow (`_pocket`, shared with the vault) stay rock and are dressed as rock, so nothing gives it away, and its chest is `hidden_until` the crack's flag. `CrackedWall.break_open()` carves them and calls `MapDresser.open_cells()`; a map built with the flag set re-breaks itself in `_ready` by the same call. Not in the sky, never in a south wall. Field rooms only, for now.
- **Teleport gates** (`TeleportGate`, `scenes/world/teleport_gate.tscn`) stand on every floor's *entry* map -- a generated floor's entrance room (`FloorGenerator.GATE_OFFSET`, placed by rule, never by the rng), Ashlow's square, Lanternfall's camp, the Town of Beginnings' plaza -- with a `gate` spawn in front of each. Touching one emits `EventBus.teleport_requested`; `ui/gate_menu.tscn` answers with the floors `GameState.visited_floors()` lists and sends the player by `SceneRouter.enter_floor(n, &"gate")`. A floor is visited when a `GameMap` for it is entered (`GameState.visit_floor()`, plus a `floor_<n>_visited` flag); the save keeps the record. The gate's base is solid and three cells wide, and the floor test's `_audit_teleport_gate` proves on all 100 floors that it cuts nothing off -- the walls-only flood fills can't see it. A new authored floor calls `_add_teleport_gate(map, cell)` and adds a `gate` spawn.
- **Adventurers' camps** (`FloorCamp`, `scripts/world/floor_camp.gd`) are a generated floor's settlement, shaped like `FloorPuzzles`: `reserve()` carves the plot once the arrival room is known, `plan()` decides what stands where before `dress()`, `place()` puts it down. **The plot is chosen by rule and carved with no rng** (`FloorGenerator._carve` asks the rng about every cell, so the camp paints its own): `FloorCamp.PLOT` (16x12, sized for the village tier) round the arrival room, `CLEARANCE` from every other room, centred where it can be and the biggest that fits where it can't. Adding it moved nothing on any floor -- fingerprint all 97 before and after any change to it, as for the labyrinth. *Who and what* stands there comes from its own stream (`hash("<seed>:camp")`); *where* is rule: nothing in a corridor's sweep (`FloorGenerator._lanes`, recorded by `_carve_line` because a corridor through a room is invisible in `_open`), every piece with a free cell, a lane or the plot's rock all round it, nothing that cuts a plot cell off from the arrival. Tents are `BiomeKit.camp_tiles` in every biome, pitched like houses (invisible `wall_alt` footprint, tile on `Props`); the cookfire is a `Campfire` with `rests = false`; campers are `Npc`s with a `Dialogue` built in code, gated on `boss_found_<n>` and `FLOOR_CLEARED`. **The camp is not a safe zone.** The floor test's `_audit_camp` checks it on every generated floor, and wants at least 80% of camps whole.
- **The camp settles into a village** once floor n+3 is cleared (`LocalQuests.is_settled()`; `FloorCamp.settle_override` forces it for tests). `FloorCamp._plan_village()` plans houses (`BiomeKit.village_tiles`, the band's own look, a `"village"` list in `build_biomes.gd`) and two settlers' spots **on every floor, settled or not**, and takes them out of the open cells the puzzles read either way -- so settling moves nothing but the houses going up (fingerprint both tiers against the old camp after any change). Built only in a village: houses pitched like tents (solid footprint on `Walls`, all rows but the roof's, the tile on `Props`), a settler outside each of two (`Settler0/1`), and a **trader** (`Trader`, the band's counter) on the first campers' cell the village leaves free and in one piece -- only ever a campers' cell, which every floor already keeps out of the puzzles' open cells, so the counter moved nothing and asks no stream where it stands. A village's **campers are gone** -- up with the front line -- and its houses may stand on their ground. A plot with no room for two houses rebuilds its second tent as a 3x3 **cabin** on the same footprint, always leaving one tent; every band has a 3x3 village tile for it. The settled plot is named "Village" on **M**. The floor test builds every settling floor a second time and wants 80% whole (a house and both settlers), and 75% with a trader.
- **A generated floor may have an event** (`FloorEvents`, `scripts/world/floor_events.gd`; picked by `FloorRegistry.event_of(n)` on its own stream, `hash("<seed>:event")`, `FloorEvents.CHANCE` of the floors that may -- never authored, floor 2, the top or a dungeon -- one a floor, never the same kind twice running; `FloorGenerator.event_override` for tests and tools). Shaped like `FloorPuzzles`: `plan()` after the puzzles and before dressing, `place()` once the camp is down, on `hash("<seed>:events")` (the cast on `hash("<seed>:event_cast")`), so **an event moves nothing**: fingerprint every floor with `event_override = NONE` against HEAD after any change. **FIELD_BOSS**: a `Monster` with `boss` (fought through `Encounter.is_boss`, drawn doubled) at `FloorTuning.field_boss_level(n)`, `defeat_flag` `event_<n>_boss`, keeping to its post (`wander_radius`) in front of a **hoard** carved by the vault's code (`FloorPuzzles.pin_vault(room, side, size)`, after `claimed()`), shut by a `SealedDoor` (`HoardSeal`) whose one sigil is that flag. **ESCORT**: an `Escortee` (`scenes/world/escortee.tscn`, an `Npc`) in the farthest room with two `Besieger`s; their job is `event_<n>_escort`, built by `FloorEvents.build()` (`QuestLibrary` hands it any `event_` id), its TALK target `event_<n>_escort_home` the thanks they say once walked into the camp's plot; taken, they follow your trail, and a monster that reaches them engages you (`Monster._touching_escort`); following is not saved. **AMBUSH**: an `Ambush` node over a room on the way to the labyrinth or arena; walking in springs the pair (`Bestiary.ambush_encounter`, `pk_swordsman`/`pk_knifer`, in no pool) as `FoeFigure`s on `stage_battle(..., 2)`, a toll or a fight; `event_<n>_ambush` once paid or beaten. **DUEL**: a `Duellist` (`scenes/world/duellist.tscn`, an `Npc`) in the camp offers a first-strike duel, `FloorEvents.stake(n)` Col against a piece of their gear; the choice sets `event_<n>_duel_accepted`, which the duellist clears and acts on once the box closes (refusing you below half HP, with no room for the wager, or short of the stake), then stages it on the map (`stage_battle(..., 1)`, a `FoeFigure` stepping up) and runs `Bestiary.duel_encounter()`. An honest win sets `event_<n>_duel` (they stay, and say so); a loss costs the stake and you can go again. A rigged one (`FloorEvents.is_rigged()`, ~a third, from the cast stream; `rigged_override` for tests) ends in a betrayal (below) and the duellist gone for good -- the veteran's line is the tell (`DUEL_TELLS`). Event NPCs are never solid. The camp's veteran says a line about it (`FloorCamp.event_line`). The floor test's `_audit_event` builds every event floor with and without it.
- **A generated floor may have a landmark** (`FloorLandmarks`, `scripts/world/floor_landmarks.gd`; picked by `FloorRegistry.landmark_of(n)` on `hash("<seed>:landmark")`, `FloorLandmarks.CHANCE` of the floors that may -- never authored, floor 2, the top or a dungeon -- never the same kind twice running and only one the band draws, `kinds_for()`: no great tree underground or in the Ruby Palace; `FloorGenerator.landmark_override` for tests and tools). A pick is what the floor *tries*: where no room fits it, `plan()` falls back to another kind, and ~5% of picks fit none. **LAKE**: water over a room but for a two-cell shore (`SHORE`, the walk round two abreast), the band's liquid, a sign in a top corner (a forest's crowns hang over a room's bottom row). **GREAT_TREE**: the pack's 48 px tree drawn twice over (a dead one in the swamp and the ash), standing on its trunk. **MONUMENT**: a statue twice over on a paved square, sandstone or grey by band, the floor's dead (`HANDLES`) cut into it. **RUIN**: the pack's arch twice over on two legs you walk between, a broken pillar, boulders, and a tablet (the pack's stele weathered grey in code, as `Chest` makes its sealed blue) that names the boss and its level. It takes a room nothing else has -- not the arrival's, the boss's, a safe zone, the event's, or one holding a puzzle's piece (`FloorPuzzles.pieces()`: `claimed()` without the ring kept round the floor's chests) -- a room with a floor chest only as a second choice, keeping a cell clear round it, and never water or stone on a wisp's path; the room's boulders and pools are cleared for it. **Three passes, all after everything else**: `plan()` after the events and before dressing, `paint()` after dressing (`MapDresser.lay_into()`), `place()` last, which puts up a `Landmark` (`scripts/world/landmark.gd`, an `Interactable`: sprites cut from the pack's sheets, each standing on the bottom edge of the cells it covers, y-sorted, solid only through its footprint on `Walls` in the invisible `wall_alt` slot), its chest (`floor_<n>_chest_landmark`, plain, from `FloorGenerator.CHEST_*`), its name on **M**, and steps any monster off it onto the nearest open cell -- moved, not dropped. `GameMap.is_covered()` counts a `Landmark`'s `cover` rects as it does props, so no fight is staged behind a crown. The camp's local -- the scout, in a camp of two -- adds `FloorCamp.landmark_line` after their opening. So **a landmark moves nothing**: fingerprint every floor with `landmark_override = NONE` against HEAD after any change, and the floor test's `_audit_landmark` holds every landmark floor to the floor without it, tile for tile outside its room. The puzzle and event with/without checks build both sides without the landmark, which is planned round them. Nothing is saved but its chest's flag; a purse dropped where a lake now stands (an older save) is put down on the nearest ground (`GameMap._nearest_ground()`).
- **A generated floor's rooms have shapes** (`RoomShapes`, `scripts/world/room_shapes.gd`): **CAVERN** (a wobbling ellipse, the authored builder's `_ellipse` rule), **L_HALL** (a corner filled), **CROSS_HALL** (four corners, arms at least `ARM` wide), **PILLARS** (2x2 pillars, `PILLAR_GAP` apart and `PILLAR_MARGIN` off the walls -- only a room ten across or down holds two, so a smaller one draws again from the rest). `CHANCE` of the rooms that may take one do, the kind by band (`WEIGHTS`: natural bands lean to caverns, built ones to halls, no pillars in the sky, whose rock is a hole). **It only ever puts rock back** into the rectangle the generator carved, planned last -- after the landmark, before dressing, so the walls join round it -- in rooms nothing else has: never the arrival's or the camp's, a boss's, a safe zone, the event's, the landmark's, a rite's or a statue ring's (a timed rite is measured against the room as it was), and in the rest a cell clear round the floor's chests, every puzzle piece (`FloorPuzzles.pieces()`), a waystone, a dungeon's levers and warden, and off a wisp's way. Rock taken from a room's edges keeps off every corridor's sweep (`_lanes`), or it would close a mouth; a pillar may stand on one. `_settle()` makes it drawable: every rock cell in a 2x2 of rock, every floor cell beside it in a 2x2 of floor (a boulder counts as floor), slivers taken in for `TAKE_PASSES` and then only rock let go, so it always settles; a shape that would cut off anything walkable from the arrival is dropped and the room stays a rectangle. Each room draws from its own stream, `hash("<seed>:room:<x>,<y>")`, so excluding one never changes another's. **The floor's rng asks what it always did**: `_add_monsters`, `_add_swarm` and a dungeon's `_add_level_monsters` count a cell in `_filled` as floor when drawing, and `step_monsters_off()` moves anyone on the rock to the nearest floor after -- moved, not dropped. So with `FloorGenerator.with_room_shapes = false` every floor is byte-identical to the floor before shapes existed (fingerprint every floor so after any change to them); with them, only the rock, the dressing and those monsters differ. `room_shape_override` forces a kind for tests and tools. The generator leaves `room_shapes` (rect → kind) and `room_rock` metadata for the tests. The puzzle, event and landmark with/without checks build both sides unshaped; the floor test's `_audit_room_shapes` holds every floor, level by level, to the floor without them. Nothing is saved: a player or a purse an older save left where rock now stands goes to the spawn / nearest ground as for a landmark.
- **The last fight** (`FinalBoss`, `scripts/world/final_boss.gd`; `ui/ending.gd`). Floor 100 stays generated; its boss is authored (`Bestiary.AUTHORED_BOSSES[100]`, `resources/enemies/hisukurifu.tres`), named `FloorTuning.FINAL_BOSS` by `boss_name()`, alone (`_escort_count` is 0 at the top -- he carries an escort's worth more Col instead, or floor 100 would pay less than 99), four bars: the paladin, the Game Master, the Developer (to *Revelation*), and `hisukurifu.exe (Not Responding)`, his texture failed to load. **He knows it is a game**: `FinalBoss` builds what he says before the fight (`prelude()`, shorter once `final_boss_met` is set, a line per `GameState.Mode`), after it (`farewell()`, the system's announcement last) and when he beats you (`defeat_lines()`) from the run itself, so it is code, not a `.tres`; what he says at each bar is `BossPhase` data. `BossGate` asks for them on the top floor only. **His fall clears the game** -- `GameState.is_floor_cleared(TOP_FLOOR)`, no new state -- and `Ending.begin()` runs itself from there, since it takes the player off the map the gate is on: white over everything (layer 129, above the router's fade), the player moved to the town's `gate` under it, the epilogue, the title's own `CREDITS` rolled, then `SaveGame.quit_to_title()` with a notice, which saves first -- so the save is in the town and Continue goes back to a castle with every floor open. The save's meta carries `cleared`, which `SaveCard` shows in gold. `Ending.pace` scales every duration for the save test.
- **`FloorTuning`** holds the whole 100-floor curve (level, map size, room/chest counts, boss names). Balance changes go there, not into individual floors.
- **Progression** is `GameState.clear_floor(n)` → `is_floor_unlocked(n+1)`. `BossGate` is the gate, and it runs a real fight (`Bestiary.boss_encounter(n)`). Losing drops the player at the floor entrance on 35% HP with the floor rebuilt, so its monsters are back — the way through a wall is levels — and leaves their purse at the door.
- **The boss steps out of its door.** A boss has nothing on the map until it is challenged, so `BossGate._step_out()` makes a `FoeFigure` per enemy (`scripts/world/foe_figure.gd`: a sprite, `sprite()` and `face()`, nothing else), fades the door aside as they fade in on its threshold, and walks them out to the formation `GameMap.stage_boss()` found before the fight starts — its own locked beat, not the runner's opening pause. The boss is anchored and the player moves: it steps up to `BOSS_STEP` cells out of the door, and the gap between you is whatever keeps the sprites apart plus a cell (`_clearance`), since a 60 px boss below you would stand on your head at a monster's three. A boss built from a 16 px trash template is drawn doubled; an authored one breathes through `EnemyType.idle_frames`. `BattleStage` closes in to ×2 only when the fighters, the pointer's headroom and the menu band fit (`BattleStage.fits()`), which every monster fight does and an authored boss faced up or down the screen doesn't.
- **Every generated floor carries `FloorTuning.monster_count(n)` roaming monsters.** That count is not decoration: it is the measured number of kills that puts a player at the level the floor's boss expects. Monsters have no solid body (they test walls to move, but nothing collides with them), so they can never wall off a corridor and the completability flood fill never sees them.
- **An authored floor ends in a labyrinth too, grown by the generator's code.** `FloorGenerator.grow_into()` grows and carves a maze into a map someone else is building; the floor script calls `_grow_labyrinth(at, cells, side, along, seed)` on the builder, carves its own corridor to `_lab.doorstep`, and after dressing `_add_labyrinth()` puts down the dark, the camp, the metadata the floor test reads, maze monsters and a dead-end chest -- all placed by the maze's seed -- while `_add_boss_gate()` hides the door in the boss room. A seed whose maze grows no camp is refused: try another. Its boss room is square (`AUTHORED_BOSS_BLOCK`, 10x10 tiles) because an authored boss is drawn full size, and the floor test wants its door half a view from the map's edge, or the x1-framed fight is pinned against it with the player under the menu. Puzzles are **pinned, not rolled**: `_new_puzzles()` then `_pin(_puzzles.pin_wisp/pin_rite/pin_statues/pin_vault/pin_crack(room, ...), what)` before dressing, `_place_puzzles()` after the chests -- the generated planners split into "which room" (rolled) and "in this room" (shared). A cave's room rect has rock in its corners, so pin to a rect inside the wobble. Gilded chests are a `gilded`/`trap` pair on a chest-table row. Changing the generator's labyrinth code must keep every generated floor's rng draws in order: fingerprint all 97 before and after.
- Adding a milestone floor: a `tools/build_floor_NN.gd` that extends `tools/authored_floor.gd` — layout tables plus a `_build()`; the base does painting, wall joining, placing entities, the labyrinth and puzzles above, the reachability check and the save — then a `FloorDefinition` `.tres` in `resources/floors/`, registered in `FloorRegistry.AUTHORED` (explicit dictionary — `res://` directory scanning is unreliable in exported builds). An authored boss also wants an id in `Bestiary.AUTHORED_BOSSES`, which overrides the archetype the floor would otherwise have been given; go in near that archetype's numbers and check the combat suite's win rate doesn't move. **Authored does not mean exempt from the curve**: a floor carries at least `FloorTuning.monster_count(n)` monsters at `FloorTuning.enemy_level(n)`, and the floor test enforces the count.
- **Floor 10 is one map, where Floor 1 is two.** Floor 1 splits town and field across a `MapExit`, which is fine there because the boss is a one-way trip. Ashlow has a quest that sends you to the Warden and then *back to the village to report*, so the walk home has to exist — and one map is the version of that walk costing no fade, no second scene and no second set of spawn points. `tools/build_floor_10.gd` is the authoring surface: layout tables at the top, the same carve/join passes the generator uses, and a flood fill that refuses to write an unfinishable floor.
- **Floor 25 is a chain, where Floor 10 is a loop**, and a one-way lift is how the chain gets you home: a `MapExit` whose `target_map` is its own scene, arriving at a `from_lift` spawn in the camp. It stands at the bottom, so the long way down is still the only way down, and the reload is the fare — the floor's monsters come back. Its caverns are `_carve_cave()` ellipses rather than rects; the wobble only pulls inwards, so a cave stays inside the rect its table gives it.

### Map dressing and the art pack

- **Everything dressing adds is visual.** `Walls` keeps every collision it had and gains none; standing things go on `Props` (y-sorted) and flat scatter on `Decor`, both with collision off. That is what keeps the floor test's flood fill — which only reads `Walls` — true without it knowing dressing exists. The floor test checks the layers stay that way.
- **A biome's wall mass has a style.** `BLOB` autotiles it; `TREES` leaves the `wall_tile` cells alone (plain grass underneath, still solid) and plants 2×2 trees over them on a staggered lattice, then fills whatever the lattice missed with a tree or a bush. The floor test refuses a forest edge with nothing standing on it — the forest's version of a mis-paired blob tile. **Cliffs are a `BLOB`, not a third style**: the pack's raised-ground autotile (`TilesetRelief.png`) draws a dozen arrangements, so `build_biomes.gd`'s `_compose_cliffs` builds all 47 from quarters, each decided only by the neighbours it touches — and a cell with open ground below is a cliff face top to bottom, since the pack draws the face inside the rock's last row. The cave repaints the tops with the pits' dark (`cliff_top`) so the rock reads as void rather than snowy plateau. After that the dresser's terrain pass and the floor test's blob checks treat it exactly like a placeholder's, which is the point. The ruins take the same blob from the relief's orange block and keep its sandstone tops — grassed over, the rock matches the rooms and the floor stops reading as rooms. The desert takes the ruins' blob too, but repaints its tops the brown of its own faces (`cliff_top`): bare, they are exactly the pale sand its corridors are made of, and a corridor read as a gap in one flat plain. The volcanic band takes the same blob with the cave's black tops: red rock under a charred crust. **The sky is a `BLOB` too, and see-through** (`_compose_hole`): the lawn is rimmed by the pack's hole (`TilesetHole.png`, a 3x3 whose strips are its outer halves side by side, with its rim nubs for inner corners), the hole's void is cut out, and under every lawn hangs a cell of earth. The pack draws no floating island, so the earth is drawn by `_underside` in the pack's colours (the spec's `underside`), its shape in the `UNDERSIDE_*` tables -- edit those and look. Where the earth runs out beside more void its rounded end is drawn by the *neighbour*, since the earth cell's own mask has dropped that corner (its north is open) and only the cell beside it sees the lawn across its corner. The sky behind is `BiomeKit.backdrop`, drawn by `_backdrop` (the pack's blue with its clouds strewn by a fixed seed, tiling seamlessly) and hung behind the map by `MapDresser.add_backdrop()` in a `Parallax2D` at half scroll -- a painted sky is a swap of that texture. Rejected: cloud as the whole mass (a snowfield), a cloud bank round the lawns (no edge to the land), the hole's own 6 px face (a fence), the relief's orange cliff face (turned down on sight). The floor test refuses any wall tile with a see-through pixel on an edge it shares with the floor, which is the one way this goes wrong that the blob checks can't see. **The castle's stone is a `BLOB` too** (`_compose_masonry`), from the pack's masonry room outline (`Interior/TilesetWallSimple.png`). Its bands are 10-13 px deep, more than half a cell, so quarters can't build it: each pixel of each blob tile is copied from the outline piece for whichever open side or corner of the mask is *nearest* it (`_nearest_floor`, sides winning ties), which reproduces every arrangement the pack draws and mitres the ones it doesn't. The floor test refuses a wall facing a hall that shows the mass's black where the band should be.
- **Ground and water join by nearest match, not `set_cells_terrain_connect`.** `MapDresser.TerrainMatcher` scores every tile of the right centre against the cell's neighbourhood and takes the closest (ties broken by the cell's hash, so repainting never reshuffles grass). Godot's solver propagates a missing arrangement into the neighbours instead of settling. Path and special slots are dirt, everything else grass. The pack draws its shores only onto its light grass, so a biome on another grass gives `liquid_palette`: two blocks of one sheet drawn alike in two palettes, from which `build_biomes.gd` reads a colour swap and repaints the shoreline — the forest's ponds, Stillwater's lake. A ground block whose dirt `_is_dirt` cannot tell from its ground (the cave's taupe, where mud is no warmer than earth) gives `ground_links`: the links are read off the meadow's block instead, **and a cell the two blocks don't draw alike is left out** (`_drawn_alike`) — the taupe block has mud in one cell where the meadow's has grass, and trusting the meadow there painted mud squares across every cavern. The floor test cannot see that failure: the tile's data is self-consistent, only its art is wrong. The swamp's bog is the pack's purple pond, drawn into the cave's taupe, so its `liquid_palette` swaps taupe for deep grass; `_is_water` reads purple as water too, and the widening left every other tileset byte-identical. **The desert's two sands are both warm**, so `_is_dirt` calls all of it dirt, and its dune lines are not the grass's tufts, so `ground_links` drops nearly every cell as not drawn alike: it gives `pale_dirt` instead, and `_is_pale` reads the path as the sand above 0.75 luminance — which comes out link-for-link the meadow's layout. Its oasis is the pack's own sand-banked pond, whose land is the *pale* sand; `liquid_land` names that pond's plain land cell and repaints its one colour to the floor's, leaving the bank's darker rings as drawn. **The ice's frozen pond is banked in snow as white as its foam**, so `_is_water` reads the whole bank as water and reading blue alone drops the foam and misses every edge the water reaches through it. Its links are read off the desert's oasis instead (`liquid_links`) — the same drawing, water pixel for water pixel, which `_same_water` checks cell by cell — and `liquid_land_regions` repaints the pond's white land to the floor's lavender only in regions that touch nothing but the ground block's colours, so the foam stays white. Its snow is the meadow's block with lavender for grass and white for dirt: `pale_dirt` is a luminance threshold, 0.75 on sand and 0.97 on snow, where the fringe is grey. **The pack draws neither lava nor ash**, so the volcanic band repaints both. Its ground is the cave's taupe block through `ground_recolour`, a typed palette whose every target `_recolour` checks against the pack's `Palette.png`. Its lava is the meadow's pond with the water's colours swapped for `liquid_ramp`'s (the pack's fire particle) rank for rank by luminance (`_lava`), and only in the liquid cells and slot, since the ramp's white is also a skull's. The swap happens on a copy *after* every link is read, so the lava's links come off the water it was drawn as, and nothing in `_is_water` had to learn orange. The floor test's edge check did: it tells lava from the desert's nearly-as-orange sand by how much redder than green it is. **The castle's path is an inlay** — the pack's brick floor block, whose frame lines are drawn in the brick's own colours, so neither `_is_dirt` nor `ground_links`' pixel comparison can read it. `ground_layout` names the meadow block it is laid out like, and `_framed_links` floods the regions between the frame lines, lets each vote by its deepest pixels against that block, and keeps a cell only if both readings agree on what the terrain can express (`_expressible`: the meadow claims a 2 px corner sliver no neighbourhood ever asks for). `ground_fill` copies a cell over the block's one blank one. Its pools are the oasis with the sand cut out (`liquid_cut`), so they sit in the brick as basins.
- **The pack draws no one-cell pond**, and nearest match gives a lone pool the cut-off end of a strip. `build_biomes.gd` composes one (`PUDDLE`) from the rounded ends of the pond block's one-wide vertical strip — measured rows, since the caps end mid-cell — and its links are read off the pixels like every other tile. Generated floors scatter pools one cell at a time, so this is most of the water they show. The floor test asks the matcher for a lone pool on every pack biome and refuses anything but an exact match — and, since a misread pond cell claims no links either and ties with the puddle by hash, it also refuses any unlinked pool tile that draws water on its edge pixels. The first check alone passed an ice build that drew stray fragments of the big pond as puddles.
- **The pack draws a transition inside the terrain's own cells.** A path cell beside grass shows dirt on its inner half, a one-wide path is a strip down the middle, and the grass around a path is always plain grass. Two consequences: a 2-wide road *reads* 1 wide, so lay roads 3 wide; and the floor test can demand exact edges (it does) — a dirt cell must describe its real neighbourhood, a grass cell must be plain.
- **Standing tiles are anchored at the bottom row of their footprint** and sort from its bottom edge. `build_biomes.gd`'s `_stand_up()` sets that (`texture_origin`, `y_sort_origin`) and `MapDresser.footprint()` is its inverse — change one, change both. The map root is `y_sort_enabled`; `Ground`/`Walls` sit at `z_index` -2 and `Decor` at -1. `GameMap`'s camera limits read only `Ground` and `Walls`, because a crown on the forest's top row hangs a row above the map.
- **Houses on authored maps** are a footprint and a prop: the bottom rows painted in the invisible `wall_alt` slot (solid), the house tile placed on `Props` with `MapDresser.anchor_for()` *after* `dress()`. The roof's top row stays walkable, so you pass behind it. `authored_floor.gd`'s `_house(rect, variant)` does both on any biome with `house_tiles` (and keeps the old roof-and-wall-course block on one without). Lanternfall's "houses" are the cave biome's camp tents, and refuses a rect that isn't exactly its house tile's size. Every biome also carries the same three tents as `camp_tiles` (`build_biomes.gd`'s `CAMP_TENTS`, rows below the blob), for generated floors' camps.
- **Characters use the pack's sheet layout**: 4 columns (down, up, left, right) by 7 rows, the first 4 the walk cycle; `Npc.sprite_sheet` picks a character, and dialogue portraits are the character's `Faceset.png`. Monsters get `EnemyType.sheet` + `sheet_frames` — 4×4 is four directions, N×1 a side view drawn facing right — and `battler` becomes an `AtlasTexture` frame of it. A boss's `FoeFigure` draws a 16 px trash template ×2 and an authored boss's own frame ×1, breathing through `EnemyType.idle_frames`.
- **Dressing is deterministic**: the seeded rng is asked in reading order, never in used-cell (hash map) order.
- Converting a biome: an entry in `PACK_BIOMES`, rebuild, and look — `tools/screenshot.gd` stands the player behind a roof, under a grove, at the pond and at the door on Floor 1 (`04j`–`04m`), in Ashlow (`04n`–`04p`) and in Lanternfall (`04q`–`04u`), which is the only way to see the depth sort.

### The UI and the pack

- **Two grounds, after SAO's own: white menus and dark glass.** The menus -- the game menu, the title, shop, forge, gate -- are white panels in dark ink with an orange cursor; whatever is drawn over the map in play -- the vitals, the dialogue box, the battle plates, the quest tracker -- is dark glass in light text, so it reads on snow and on grass alike. Frames are Kenney's Fantasy UI Borders (CC0, `assets/kenney_fantasy_ui/`, `.gdignore`d -- only the tool reads them): one pixel of line, one of gap where the ground shows through, then the fill.
- **Both themes are built, never hand-edited.** `tools/build_ui_skin.gd` halves the pack's 2x art, paints each frame's line and fill in `UiPalette`'s frame colours, reads the nine-slice margin off the drawing, and writes `ui/theme/gao_theme.tres` and `ui/theme/glass_theme.tres` with the textures embedded. A new role or a recolour: a line in the tool (or a colour in the palette), run it, look.
- **One Theme for every screen, and glass where the map shows.** `gao_theme.tres` is applied project-wide (`gui/theme/custom`), so a Control wears the menus by existing; the over-map scenes set `theme = glass_theme.tres` on their top-level Controls, which overrides it for everything under them. Screens choose a *role* with `theme_type_variation`, never with local styleboxes: `PanelContainer` is the window (square knots in the corners), `MenuWindow` the same with thin sides for the game menu (its pages bring their own framed panels; System, the one drawn straight on the window, pads itself), `InsetPanel` the plain white info panel, `CardLit` the card under the cursor, `HudPanel` the glass plate for anything over the map (glass in both themes), `DialogPanel` (stepped corners) / `ChoicePanel` / `NameTag` the conversation's glass, `FacesetFrame`, `CellPanel` the bag slot, `FocusFrame` the cursor frame, `TabOn` / `TabOff` / `TabHover` the tabs, `MenuRow` / `MenuRowFocus` / `MenuRowLocked` a menu's plates, `MapPanel` the map's dark sheet, `BadgePanel` a small red tag (a Hardcore slot); labels are `HeaderLabel`, `HintLabel`, `InkLabel` (the ground's own text colour), `FieldLabel` (text straight on the map or a backdrop, shadowed), `MapLabel`, `BadgeLabel`, `CountLabel` (a bag cell's count) and `TitleLabel`. `Button` and `ProgressBar` are themed by type; a menu row that destroys something is tinted red (`MenuList`'s `danger`). A tint that varies at runtime — a bag cell's rarity, a drop target's green — is the node's `self_modulate`, not a duplicated stylebox.
- **Colours that mean something live in `UiPalette`** (`ui/theme/ui_palette.gd`), not in each screen — ready, done, locked, tracked, targeted, the SAO health colours, drop and the empty bag slot. There are two grounds and two sets: the plain names (`TEXT`, `READY`, ...) are ink for the white menus, `GLASS_*` light text for the glass, and an item's rarity is `rarity_ink()` on white (`Item.rarity_color()` is for dark ground and cell tints). Writing on the orange cursor is `ON_ACCENT`. `UiPalette.paint_bar()` recolours a bar's fill and keeps the theme's outlined shape.
- **Lay screens out in 640×360 units.** That is the base viewport, twice the map's pixel density (`UiLayout.WORLD_ZOOM`): a frame's one-pixel line is half a world texel, so the chrome is fine where the map is chunky. Pixel art in the UI is drawn at a whole multiple -- a pack keycap or the cursor arrow at 1x, a faceset at 1x (each texel a world pixel's size), a bag icon at 2x in its 36-unit cell -- or halved (a 24 px skill icon in the combat menu), never any other fraction.
- **The font is Exo 2** (SIL OFL, `assets/fonts/Exo2-Variable.ttf` with its `OFL.txt`), a variable font: `tools/build_ui_skin.gd` writes it as two `FontVariation`s, `ui_font.tres` (weight 520, text) and `ui_font_strong.tres` (680, `HeaderLabel` and `TitleLabel`). Text is 12 units (`TEXT_SIZE`; a line is 15 tall), titles 24, the title screen's logo 64. The stretch mode is `canvas_items`, so text is rasterised at the window's resolution and stays smooth at any window size -- the hand-drawn pixel font it replaced looked crude at 4x. Its import turns hinting off and positions glyphs to a quarter pixel (`Exo2-Variable.ttf.import`): with Godot's defaults the 2x stretch spaces letters unevenly ("Dea th"). System fallback is off, so a glyph the font lacks shows as missing in a screenshot rather than borrowed from the machine; the pack's `Arrow.png` is still the continue marker and the target pointer. Shadows (`font_shadow_color`, offset 1) are what lift text off the map. Neither of the pack's fonts is used: `NormalFont.ttf`'s `i` is a stub with its dot knocked sideways and its word space is 2 px, so "Kirito" reads "K.r.to"; `font8x8.png` draws capitals and digits in 2 px strokes six tall beside 1 px lowercase, so every capital looks bold.
- **Text sits clear of every frame.** The window's knotted corners reach 5 units in, so its content margins are 10 at the sides and 8 top and bottom (a line's own ascent and descent give the rest) -- the inset keeps the same, though its plain frame is 2; the lit and unlit cards share them so nothing moves. Every margin is a `*_PAD` in the skin tool. Where that leaves too little room, the page gives way -- shorter columns, a line folded into another -- never the margin: the save test draws every item's details and every quest's page and fails one that overflows, since a page that outgrows the menu window pushes it over the key line.
- **The conversation box is 66 of the screen's 360.** Its height is set by the *portrait*, not by the text -- up to 40 units of faceset (`FACE_ROOM`) inside a 4-unit frame, three lines of text beside it -- so shrinking the box means shrinking the face. A portrait is halved until it fits that room, never scaled by any other fraction: the pack's 38 px facesets draw whole. The fight's plates keep to the band `BattleStage.FRAME_LIFT` frames the fight above (24 world pixels, 48 units). Dialogue text is `vertical_alignment = 1`, because one line in a three-line box reads as centred and not as stranded against the top edge.
- **A `PanelContainer` grows to fit but never shrinks back.** Anything shrink-wrapped — the dialogue name tag and choices, the combat menu, the interact prompt — is anchored at the corner it grows away from and collapsed to a 1 px rect after its contents change by `UiLayout.shrink_wrap()`, which keeps the edge its grow direction says stays put; the container's minimum size does the rest. Things that appear and disappear inside a row (the continue arrow, the target pointer) hide by alpha, so the row never reflows.
- **One cue per meaning in the bag.** The orange focus frame is the cursor and only the cursor; the cell's tint is rarity, and turns `UiPalette.DROP` green where a dragged stack may land. The journal keeps its rule: the cursor arrow is where you are, colour plus glyph is what the quest is.
- Adding a screen: a `CanvasLayer`, panels with a `theme_type_variation`, colours from `UiPalette`, text at the theme's size. Frame it in `tools/screenshot.gd` and look.

### The audio

- **All of it is the Ninja Adventure pack's** (`assets/ninja_adventure/Audio/`: 40 tracks, jingles, sounds), named by id in two tables: `SoundLibrary.SOUNDS` (`scripts/audio/sound_library.gd`: id → files, `db` to even the pack's levels, `spread` to detune repeats, `jingle`) and `MusicLibrary.TRACKS` (`scripts/audio/music_library.gd`). Nothing else builds a path to an audio file but `Weather.LOOKS`, whose loops are its own.
- **`Audio` (autoload) is a view**: nothing reads it, and a game with no sound plays the same. What `EventBus` already announces it hears for itself -- a level, a quest taken or done, a door found, the purse paid outside a fight, a field potion, a full bag, a forge's success, a manual save, a fight fled, the idle countdown's last ten seconds, a logout -- so those systems never learn there is a speaker. What only a node knows it asks for: `Audio.play(&"chest")` from the lid, the crack, the seal, a cursor moving. Keep to that split: a new bus signal worth a sound is a line in `Audio._ready`, not a call in the system that emits it.
- **Music is place, then fight.** `GameMap` emits `EventBus.map_area_entered(map, area)` from its fog-of-war step when the player's cell changes kind (`area_at()`: `SAFE` in a safe zone, `DARK` in `dark_area` outside `lit_areas`, else `OPEN`) and once on arrival; `MusicLibrary.for_place()` gives the track -- the safe zone's or the labyrinth's on every floor, else `GameMap.music` (the town's) or the band's (`biome_id`). `CombatManager.combat_began` lays the fight's track over it (`for_fight()`: fight, boss, the top floor's last boss), `combat_finished` takes it off with the fanfare (victory, a boss's, defeat; nothing for a flight). Two decks crossfade (`FADE`, quicker into a fight); a place's track picks up where it was left, a fight's starts from the top. The title plays its own on `title_requested`; the credits page asks `Audio.play_over(&"credits")`.
- **Jingles take turns** on one player, the music ducked to `DUCK` under them; one asked for while another plays waits (at most `QUEUE`, never twice). A level gained in a fight is held until the fight's fanfare is under way.
- **Sounds** come from a pool of `VOICES` players on the Sounds bus; the same id twice inside `SAME_SOUND_MS` is one sound (three hits landing together, every monster on a floor noticing at once). An unknown id warns and plays nothing. `Audio.played(id)` is the tests' spy.
- **A fight's blows are the effect's**: `SkillFx.sound` names the sound a skill (or a monster's plain attack, through `EnemyType.strike_fx`) lands with; `BattleStage._hear()` plays it, a whoosh if every hit missed, a crack over a crit or stagger, its own for a guard, a poison's tick and a fall -- all skipped when `step_delay` is 0, like the rest of the stage.
- **Buses**: `default_bus_layout.tres` -- Music and Sounds, both into Master. `Settings.apply_audio()` is the only thing that sets their volume. A storm's loop (`Weather`) is on Sounds and plays only once its map is in the tree, so a floor built by a test or tool is silent.
- **Every track loops and no sound does** -- an import setting (`loop=true` on every `.ogg` in `Musics/`, `edit/loop_mode=2` on the weather's three ambient `.wav`s); the audio test holds both. A new track: its import's `loop`, a line in `TRACKS`. A new sound: a line in `SOUNDS`, then `Audio.play(&"id")`.

## Godot 4.7 gotchas

- GDScript 2.0 syntax: `@export`, `@onready`, `signal name(args)`, `await signal_or_coroutine`, typed variables (`var hp: int = 10`). Do not use Godot 3.x idioms (`export var`, `yield`, `.instance()` → now `.instantiate()`).
- Every `.tscn`/`.gd`/asset has a companion `.uid`/`.import` or embedded UID; when moving files, use the editor's FileSystem dock (or update references) so `uid://` and `res://` paths stay valid.
- Rendering is **Mobile** and stretch mode is `canvas_items` with `expand` aspect — the 2D UI scales cleanly across resolutions; design UI with anchors/containers, not fixed pixel positions. The base viewport is 640x360, so UI is laid out in those units.
- `TileSetAtlasSource` must be added to the `TileSet` *before* creating tiles, or the tiles get no physics layers and every collision-polygon call fails silently-ish (an error per tile).
- GDScript lambdas capture locals **by value** — a lambda that writes to a captured local silently discards the write. Use a member variable for signal spies and accumulators.
- `Input.action_press()` sets the action's *state* but never synthesises an event, so nothing in `_unhandled_input` sees it. To drive UI from a tool or test, feed a real `InputEventAction` through `Input.parse_input_event()` (see `tools/screenshot.gd`).
- **A tile painted at runtime gets its collision on a later frame.** `set_cell()` on a `TileMapLayer` queues the physics update; a raycast in the same physics tick sees through the new wall. A test that paints geometry should wait a few physics frames before anything looks at it.
- **A `--script` tool must not name a game class that preloads scenes.** Naming `FloorGenerator`, `FloorPuzzles` or `Chest` -- as a type, a call or an enum -- compiles it with the tool's own script, before the autoloads exist, and with it every scene it preloads, whose scripts then fail on `EventBus`. `tools/authored_floor.gd` loads them by path at runtime (`load(GENERATOR).grow_into(...)`), keeps them in untyped vars, and mirrors the two enums it needs (`Side`, `Rite`), asserting they still match. `MapDresser` is safe to name: it preloads nothing that reaches an autoload.
- **`PortableCompressedTexture2D` drops its source buffer outside the editor.** A `--script` tool that builds one and saves it writes an empty texture, and every tile of a TileSet using it then fails to load ("Cannot create tile... outside the texture"). Set `keep_compressed_buffer = true` before `create_from_image()`.
- **`TileData.texture_origin` moves a tile's texture up and left** — it is drawn at the cell centre − size/2 − origin — and a multi-cell atlas tile is drawn centred on the cell it is placed in.
- **The screenshot window is not always vsynced, so `tools/screenshot.gd` waits on state, never on a frame count.** `_until()` polls a predicate against a wall-clock bound and `_typed()` waits for the typewriter to land. Combat paces itself on timers and the typewriter is a tween: run the window uncapped and a frame budget expires before the first `step_delay` is out, so the shot of the command menu is a shot of an empty screen, and the submit that follows is refused by a runner that never asked for anything -- which leaves the pass spinning on a fight that can no longer end. A refused submit now warns.
- **`await some_signal` parks unconditionally**, even if the thing you are waiting for already happened during the emit that preceded it. Any coroutine that emits a request and then awaits the reply needs a "did it already answer?" check first, or a synchronous responder deadlocks it. `CombatManager._decide()` is the worked example.
